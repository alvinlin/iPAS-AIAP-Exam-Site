壹、考試科目與評鑑內容

這一章是「考試說明書」：告訴你 AI 應用規劃師要會什麼、初級兩科各考哪些主題。內容不難，但常被當成送分題（例如「職能基準包含哪三種能力」）。

職能基準與報考資格 完整教材 ↗

💬 白話說「職能基準」就像一份職缺說明書加上考核表：它把某個職業要做的事拆開，再寫清楚做這些事需要「懂什麼（知識）、會做什麼（技能）、用什麼心態做（態度）」。AI 應用規劃師不是寫模型的工程師，而是企業裡的 AI 導入顧問兼專案經理：懂工具特性、能依部門需求挑對工具、能拉著跨部門團隊把導入計畫做完，並在上線後持續優化。
🧠 記憶口訣知技態、懂挑帶
職能基準＝知識＋技能＋態度；規劃師的工作＝懂工具、挑方案、帶團隊導入。

📖 名詞小辭典

職能基準Occupational Competency Standard
完成某職業工作任務所需的能力組合，包含知識、技能、態度三者。例：餐廳廚師的職能基準會寫「懂食材衛生（知識）、會刀工（技能）、守時負責（態度）」。
知識／技能／態度Knowledge / Skill / Attitude（KSA）
知識是「知道什麼」、技能是「做得出來」、態度是「做事的價值觀與行為習慣」。例：知道個資法（知識）、會操作提示詞（技能）、不把客戶資料丟進公開聊天機器人（態度）。
AI 應用規劃師AI Application Planner
協助企業規劃與推動 AI 技術或工具導入的角色：評估、選型、整合跨部門、推動開發部署與後續優化。例：幫行銷部挑一套文案生成工具，並訂出試用、驗收與教育訓練計畫的人。
演算法Algorithm
解決問題的一套明確步驟。例：食譜就是做菜的演算法；排序、推薦也都有各自的演算法。
機器學習Machine Learning, ML
讓電腦從資料中自動找出規律，而不是由人一條條寫規則。例：看過大量垃圾信後，自己學會判斷哪封是垃圾信。
深度學習Deep Learning, DL
機器學習的一支，用很多層的神經網路自動學出特徵。例：人臉辨識、語音轉文字、ChatGPT 背後的模型都是深度學習。
商業智慧Business Intelligence, BI
把企業資料整理成報表與儀表板，協助管理決策的技術與流程。例：每天早上主管看的「各門市營收儀表板」。
生成式工具Generative AI Tools
能根據指令產生新內容（文字、圖、音、影、程式碼）的 AI 工具。例：ChatGPT 寫信、圖像生成工具畫海報。
ChatGPTChat Generative Pre-trained Transformer
OpenAI 推出的對話式生成 AI 服務，名稱中 GPT 意為「生成式預訓練 Transformer」。例：問它「幫我把這段會議紀錄整理成三點」。
跨產業適用Cross-industry
職能內容不限定特定行業，製造、金融、零售、醫療等都適用。例：無論是銀行還是工廠，都需要有人規劃 AI 導入。
📌 考試重點職能基準＝知識、技能、態度三者的組合；AI 應用規劃師職能重點是「了解 AI 工具特性、依業務需求評估選擇工具、整合跨部門共同制定與執行導入計畫（開發、部署、後續優化）」；此職能基準跨產業適用。
🚀 延伸與新進展考試範圍外
  • 「AI 素養」成為法定義務（2025）：歐盟《人工智慧法》（EU AI Act）第 4 條要求提供者與部署者採取措施提升員工的 AI 素養，自 2025 年 2 月 2 日起適用。這讓「懂 AI 工具、能帶導入」的規劃師能力，從加分項變成企業合規需求的一部分。
  • 規劃師的工作對象從「工具」擴大到「代理」（2025）：2025 年起 AI Agent（能自行規劃步驟、呼叫工具完成任務的 AI）成為企業導入主流議題，規劃師除了挑工具，還要設計「AI 可以自動做到哪一步、哪一步一定要人確認」。詳見 3-4。

考科內容說明 完整教材 ↗

💬 白話說初級兩科像是「上下集」：科目一教你 AI 是什麼、資料怎麼處理、機器學習怎麼運作（原理篇）；科目二教你把生成式 AI 拿到公司裡用：先認識 No Code／Low Code，再認識生成式 AI 的應用與工具，最後學怎麼評估、規劃導入並管好風險（實戰篇）。

📖 名詞小辭典

評鑑主題／評鑑內容Assessment Topics / Content
官方公告的出題範圍；主題是大分類，內容是底下的細項。例：主題「生成式AI 導入評估規劃」下有「導入評估、導入規劃、風險管理」三項內容。
鑑別式 AIDiscriminative AI
負責「判斷、分類、預測」的 AI，學的是輸入與答案之間的界線。例：判斷一筆交易是否為盜刷、X 光片是否有異常。
生成式 AIGenerative AI, GenAI / GAI
負責「產生新內容」的 AI，學的是資料本身長什麼樣子，再生出相似的新東西。例：寫報告、畫插圖、生成配音。
AI 治理AI Governance
組織用來確保 AI 被安全、合法、負責任使用的規則、流程與責任分工。例：公司規定「哪些資料不得輸入外部 AI 服務、誰負責審核 AI 產出」。
📌 考試重點科目二三大評鑑主題：No Code／Low Code 概念（基本概念、優勢與限制）、生成式AI 應用領域與工具使用（應用領域與常見工具、如何善用工具）、生成式AI 導入評估規劃（導入評估、導入規劃、風險管理）。風險管理歸在第三個主題之下。
⚠️ 易混淆「鑑別式 vs 生成式」屬科目一的評鑑內容，但科目二的情境題常拿來考：要判斷／分類（詐欺偵測、影像判讀）選鑑別式；要產出內容（報告、文案、圖片）選生成式。把生成式 AI 拿去直接下醫療影像結論，可能產生與影像不符的內容而誤判。

貳、No Code / Low Code 概念

本章主軸：No Code／Low Code 把「寫程式」的門檻降低，生成式 AI 再把門檻降得更低，兩者結合推動了「AI 民主化」。考題最愛考 No Code 與 Low Code 的差別、平台選擇六因素、挑戰與解方、市場價值三面向。

基本概念與差異 完整教材 ↗

💬 白話說想像要做一個「請假申請 App」：
・No Code 像樂高積木：只有現成積木，拖一拖、接一接就能做出東西，完全不用寫程式；但積木形狀固定，想做特殊造型就做不到。
・Low Code 像樂高＋可以自己削的木塊：大部分用積木，卡關的地方寫一點程式補上，所以能接公司的 ERP、做複雜的簽核規則。
所以 No Code 給「不會寫程式的業務人員」快速做原型；Low Code 給「有點技術底子的開發者」做企業級、可擴展的系統。
🧠 記憶口訣零碼拖拉做原型，低碼補碼做企業
No Code：零程式碼、拖放、非技術者、快速原型與小型應用；Low Code：少量程式碼、有技術背景、複雜邏輯、企業級、彈性高可擴展。
比較No CodeLow Code
誰用非技術背景（市民開發者）具基本技術背景的開發者
怎麼做圖形化介面、拖放視覺化工具＋少量程式碼
適合快速原型、小型應用、簡單業務問題複雜邏輯、企業級應用、高自訂性
客製彈性較低較高，可深度整合與擴展

📖 名詞小辭典

No Code（無程式碼）No Code
透過視覺化介面與拖放操作，不寫任何程式碼就能開發應用的方式與平台。例：用表單工具＋自動化流程工具，拖拉出「填表後自動寄信通知主管」。
Low Code（低程式碼）Low Code
以視覺化開發為主、再用少量程式碼補足整合與客製邏輯的開發方式。例：用 Low Code 平台做好畫面，再寫一小段程式去串公司 ERP 的庫存資料。
拖放Drag-and-drop
用滑鼠把元件拖到畫面上放好的操作方式。例：把「按鈕」元件拖到表單下方。
視覺化介面／圖形化介面Visual Interface / GUI（Graphical User Interface）
用圖示、方塊、連線等圖形來操作與設計，而非輸入文字指令。例：用流程圖方塊拉出「如果金額大於一萬就送經理簽核」。
使用者介面User Interface, UI
使用者看到並操作的畫面與元件。例：App 的按鈕、選單、輸入框。
快速原型設計Rapid Prototyping
先做出一個「能用但陽春」的版本，讓使用者試用並回饋，再決定是否正式開發。例：兩天內拖出一個訂便當 App，給同事試用一週。
客製化／擴展性Customization / Extensibility
依需求修改功能的程度／未來增加功能、串接其他系統的能力。例：Low Code 能加自訂程式，擴展性較 No Code 高。
TensorFlow／KerasTensorFlow / Keras
常用的開源深度學習框架；Keras 是較高階、易用的介面。指引提到它們已推出視覺化工具，讓無程式經驗者也能建模。例：用網頁上的視覺化工具調整神經網路層數、觀察訓練結果。
數位轉型Digital Transformation
用數位技術重新設計企業的流程、產品與商業模式，不只是把紙本變電子檔。例：從人工排班改成依銷售預測自動排班。
人工智慧Artificial Intelligence, AI
讓機器展現類似人類智慧（理解、推理、學習、生成）的技術總稱。例：語音助理、推薦系統、聊天機器人。
📌 考試重點No Code＝非技術背景、無需寫程式、快速原型／小型應用；Low Code＝具技術背景、少量程式碼、複雜邏輯／企業級應用、彈性較高、可深度整合與擴展。題目若問「哪一種更適合開發靈活且可擴展的解決方案」→ Low Code。
⚠️ 易混淆Low Code 的「Low」是少量程式碼，不是「低品質」；No Code 也不是「沒有程式」，而是程式由平台在背後產生，使用者看不到。另外「No Code 適合中大型企業複雜應用」是錯誤敘述，那是 Low Code 的定位。
🚀 延伸與新進展考試範圍外
  • Vibe coding（氛圍寫程式）（2025）：由 Andrej Karpathy 於 2025 年 2 月提出，指用自然語言描述需求、讓 AI 生成並修改程式，使用者幾乎不看程式碼；Collins 詞典選為 2025 年度詞彙。它把「No Code」推進到「用說的寫程式」，但也繼承了 No Code 的老問題：使用者不懂背後邏輯，品質、資安與維護風險更高，正式系統仍需工程把關。
  • AI coding agent（AI 程式代理）（2025）：例如 Anthropic 於 2025 年 2 月以研究預覽推出的 Claude Code（在終端機中讀寫專案檔、執行測試），以及 GitHub 於 2025 年 5 月 Build 大會發表的 Copilot coding agent（可把 issue 指派給 AI，在沙箱中改程式並開 pull request 待人審核）。和指引裡「自動生成程式碼」的差別：舊做法是「AI 補一段程式」，新做法是「AI 自己規劃、修改多個檔案並驗證」，人改當審查者。

生成式AI 強化 NC/LC 完整教材 ↗

💬 白話說原本的 No Code 平台像一間「自助 DIY 工作室」，工具都擺好了但要自己動手；加上生成式 AI 之後，工作室多了一位會聽人話的助理：你說「幫我做一個請假表單，主管核准後寄信」，它就先幫你把表單、流程、文案、甚至介面設計都擺出初稿，你只要微調。
🧠 記憶口訣碼、模、數、介、文、個
六項強化：自動生成程式碼、模板設計優化、數據分析與決策、AI 驅動 UI/UX（介面）設計、行銷文案生成、個人化 App 快速開發。

📖 名詞小辭典

DALL-EDALL·E
OpenAI 的文字生成圖像模型，輸入文字描述即可產生圖片。例：「一隻戴安全帽的柴犬在工地，扁平插畫風」。
自動生成程式碼Code Generation
由 AI 依自然語言描述產生程式碼。例：「寫一個把 Excel 每列寄成 Email 的腳本」。
模板Template
預先設計好的版型或流程範本，可直接套用再修改。例：報價單模板、客服回覆模板。
使用者體驗User Experience, UX
使用者操作產品時的整體感受：好不好找、好不好用、順不順。UI 是外觀，UX 是體驗。例：結帳只要三步而不是七步，就是 UX 改善。
個人化Personalization
依每位使用者的資料與行為提供不同內容或功能。例：購物 App 首頁依你的瀏覽紀錄推薦商品。
部署Deployment
把開發好的應用或模型放到正式環境讓使用者使用。例：把測試版 App 上架到公司內部 App 商店。
📌 考試重點生成式 AI（如 ChatGPT、DALL-E）對 NC/LC 的強化：自動生成程式碼、模板設計優化、數據分析與決策、AI 驅動 UI/UX 設計、自動化行銷文案生成、個人化 App 快速開發，目標是「自動化、智慧化開發與應用」。
🚀 延伸與新進展考試範圍外
  • 函式呼叫（Function calling）（2023）：OpenAI 於 2023 年 6 月在 API 推出，讓模型依開發者提供的 JSON 規格「回傳要呼叫哪個功能、帶什麼參數」，再由程式實際執行。這讓 No Code 自動化平台可以把「一句話需求」轉成對 CRM、試算表、Email 等系統的實際操作，而不只是產出一段文字。
  • 結構化輸出（Structured Outputs）（2024）：OpenAI 於 2024 年 8 月推出，讓模型輸出保證符合指定的 JSON Schema。對 NC/LC 平台很關鍵：AI 產出的資料格式穩定，下一個流程節點才接得住，不會因為多一個逗號就整條流程壞掉。

顧客關係管理系統Customer Relationship Management, CRM
記錄與管理客戶資料、互動歷程、銷售機會的系統。例：業務打開客戶頁面就看到過去的詢價與客訴紀錄。

系統整合能力System Integration
平台能否與既有系統互通資料、串接流程。例：No Code 表單送出後自動寫入 ERP。
加密Encryption
把資料轉成沒有金鑰就看不懂的形式，保護儲存與傳輸中的資料。例：網址列有鎖頭的 HTTPS 連線就是傳輸加密。
身份驗證Authentication
確認「你是誰」。多重安全機制常指多因素驗證（Multi-Factor Authentication, MFA）。例：輸入密碼後還要輸入手機收到的驗證碼。
權限管理Access Control / Authorization
決定「你能做什麼、看什麼」，細緻到依角色、欄位設定。例：業務看得到客戶電話，但看不到成本價。
總擁有成本Total Cost of Ownership, TCO
擁有並使用一項方案的全部成本：購買／訂閱費加上建置、整合、訓練、維運、資安合規等直接與隱性成本。例：軟體一年訂閱 10 萬，但串接與教育訓練又花 20 萬，TCO 是 30 萬以上。
投資報酬率Return On Investment, ROI
投入能換回多少效益的比例，常見算法＝（效益−成本）÷ 成本。例：花 100 萬、一年省下 150 萬人力成本，ROI＝50%。
應用程式介面Application Programming Interface, API
系統之間約定好的「點餐窗口」，讓程式能呼叫另一個系統的功能或資料。例：網站透過金流 API 完成刷卡。
公式ROI ＝（效益 − 成本）÷ 成本 × 100%　　回收期 ≈ 導入成本 ÷ 每期淨節省
📌 考試重點六個關鍵因素要能背出並對應內容：安全性與合規性包含加密、身份驗證、多重安全機制、細緻的權限控制；成本與效益指 TCO 與 ROI；功能與擴展性包含與 CRM、ERP 整合與高度自訂性。
⚠️ 易混淆TCO 是「成本」面，ROI 是「效益相對成本」面。導入後省下的人力或油料是效益，不要算進 TCO。身份驗證（你是誰）≠ 授權／權限（你能做什麼）。

挑戰與因應策略 完整教材 ↗

💬 白話說讓生成式 AI 進到 NC/LC 平台，就像讓一位很會寫但偶爾亂講的實習生直接幫你做系統：他可能寫錯（準確性）、把客戶資料貼到不該貼的地方（隱私）、寫出偏頗或假的內容（倫理）、做出來的東西接不上公司系統或跑不動（整合與效能）。對策就是：有人覆核、資料上鎖、訂行為準則、選開放好串接的平台。

一般資料保護規則General Data Protection Regulation, GDPR
歐盟的個人資料保護法規，規範個資的蒐集、處理與跨境傳輸，違規罰款很重。例：歐洲客戶可要求企業刪除他的個資。

自動化檢測加上人工審核，層層把關輸出結果。例：AI 產生的程式先跑自動測試，再由工程師審查。

透過網路租用遠端的運算、儲存資源，按用量付費並可彈性擴充。例：促銷期間自動多開幾台雲端主機分散負載。

讓人類在流程關鍵處參與審核與決策，AI 負責大量重複工作。例：AI 草擬理賠回覆，金額超過門檻時由專員確認。
壓力測試Stress Testing
在高負載或極端情境下測試系統表現。例：模擬一萬人同時詢問客服機器人。
弱點掃描Vulnerability Scanning
用工具定期檢查系統是否有已知的安全漏洞。例：每月掃描平台套件是否有未修補的漏洞。
資料偏見Data Bias
訓練資料不具代表性或含歷史歧視，導致模型輸出偏頗。例：過去錄取者多為男性，模型便偏好男性履歷。
📌 考試重點挑戰↔解方的配對：準確性與可靠性→多層次驗證（自動化檢測＋人工審核）；資料隱私與安全（GDPR、CCPA）→加密、匿名化、權限控管；道德倫理（虛假資訊、偏見歧視）→倫理準則、使用規範、公平性檢測；技術整合與適配→具 API 擴充能力的開放式平台、雲端分散負載。

技術架構與關鍵特徵 完整教材 ↗

💬 白話說把大型語言模型想成一位讀過整座圖書館的接龍高手：
① 訓練資料處理：先把書整理乾淨（清洗），切成一個個小字塊（Token 標記化），再把每個字塊換成一串數字（向量化），因為電腦只懂數字。
② 深度學習網路：用很多層神經網路讀這些數字；其中「自注意力」讓它讀到「它」這個字時，會回頭看前文到底指誰，即使相隔很遠。
③ 推理機制：真正回答時，模型每次都在猜「下一個字」，手上有一張「每個候選字的機率表」。溫度決定要不要冒險選冷門字；Top-k 只從前 k 名裡抽；核採樣則從「機率加起來到 90%」的那一群裡抽。
🧠 記憶口訣洗、切、量；溫越高越敢講
訓練資料處理三步：數據清洗→標記化（切）→向量化。溫度低＝保守穩定，溫度高＝有創意但較易離題；Top-k 看「名次」，核採樣（Top-p）看「累積機率」。

📖 名詞小辭典

生成對抗網路Generative Adversarial Network, GAN
由「生成器」造假、「判別器」抓假，兩者互相對抗而越來越強的生成模型。例：偽鈔師傅和驗鈔員互相較勁，最後偽鈔幾可亂真。
變分自編碼器Variational Autoencoder, VAE
先把資料壓縮成一個機率分布的「潛在空間」，再從中取樣還原出新資料的生成模型。例：把人臉壓成「年齡、表情、髮型」等旋鈕，轉動旋鈕就生成新臉。
Transformer（變換器）Transformer
2017 年提出、以注意力機制為核心的神經網路架構，是 GPT 等大型語言模型的基礎。例：ChatGPT 的「T」就是 Transformer。
多層神經網路Multi-layer Neural Network
由多層「神經元」組成，每層把輸入轉換成更抽象的特徵。例：影像辨識中，前幾層看線條，後幾層看出眼睛、輪子。
特徵提取／表示學習Feature Extraction / Representation Learning
從原始資料中自動找出有用的特徵，並學會用合適的方式表示資料。例：模型自己學到「肺部陰影形狀」是判讀關鍵。
注意力機制Attention Mechanism
讓模型處理資料時，對不同部分給予不同重視程度。例：翻譯「銀行」時，注意到前文的「河邊」而翻成 bank（河岸）。
自注意力Self-Attention
序列中每個字都去看同一序列的其他字，計算彼此關聯，擅長處理長距離依賴。例：「小明把書借給小華，因為他很需要」，模型判斷「他」指小華。
長距離依賴Long-range Dependency
句子或文件中相隔很遠的字詞之間的關聯。例：第一段提到的主角名字，在第五段用代名詞出現。
數據清洗Data Cleaning
移除雜訊與錯誤資料、填補遺缺值，確保資料品質與一致性。例：刪掉重複的網頁、修正亂碼。
雜訊Noise
資料中無意義或錯誤、會干擾學習的部分。例：爬來的網頁裡夾雜廣告與選單文字。
遺缺值Missing Value
資料中本應有值卻空白的欄位。例：客戶資料表中「年齡」欄空白。
標記化Tokenization
把文字切成模型處理的基本單位 Token（詞或子詞）。例：「unhappiness」可能切成 un／happi／ness。
Token（詞元）Token
模型讀寫文字的最小單位，也是 API 計費與長度限制的單位。例：一篇文章約幾千個 Token，費用依 Token 數計算。
向量化Vectorization
把文字或其他資料轉成數值向量；語意相近的內容向量也相近（常稱嵌入 Embedding）。例：「貓」和「小貓」的向量距離很近。
推理（推論）Inference
模型訓練完後，實際接收輸入並產生輸出的過程。例：你在 ChatGPT 按下送出後，它產生回答的階段。
溫度參數Temperature
控制生成隨機性：低溫較保守、一致；高溫較有創意、多變。例：寫合約條文用低溫，想廣告標語用高溫。
頂部採樣Top-k Sampling
只從機率最高的前 k 個候選中抽選下一個字。例：k＝5，就只在前五名候選字中抽。
核採樣Nucleus Sampling（Top-p Sampling）
從機率由高到低累加、達到門檻（如 0.9）的候選群中抽選，候選數量會隨情境變動。例：答案很明確時只剩 2 個候選；開放題時可能有 50 個。
遷移學習Transfer Learning
把在大量資料上學到的能力，轉用到新的任務。例：會中文寫作的模型，稍加訓練就會寫公司公文。
多模態Multimodal
同時處理文字、圖像、聲音、影片等多種資料型態。例：拍一張故障零件照片，問 AI 可能原因。
提示詞Prompt
給生成式 AI 的輸入指令與內容；可透過提示詞控制生成（可控生成）。例：「用國小五年級聽得懂的話解釋通膨，限 100 字」。
AI 幻覺AI Hallucination
模型生成看似合理、實際錯誤或捏造的內容。例：AI 引用一篇根本不存在的論文或判決。
模型壓縮Model Compression
縮小模型大小與運算量的技術總稱（剪枝、量化、蒸餾等）。例：把伺服器級模型壓到筆電能跑。
量化Quantization
用較少位元表示模型參數（如 16 位元→4 位元），省記憶體、加速運算，可能略損精度。例：像把高畫質照片轉成檔案較小的版本。
推理加速Inference Acceleration
讓模型產生回應更快、更省資源的各種技術。例：改良記憶體管理，讓同一張 GPU 同時服務更多使用者。
混合注意力機制／模塊化設計Hybrid Attention / Modular Design
結合多種注意力計算方式以兼顧效率與效果／把模型拆成可替換、可組合的模組。例：只對附近字詞做完整注意力，遠處用簡化方式計算。
領域特定微調Domain-specific Fine-tuning
用特定領域資料再訓練通用模型，讓它更懂該領域。例：用法律判決書微調，讓模型更會寫法律分析。
📌 考試重點生成式 AI 常基於 GAN、VAE、Transformer。三大環節：深度學習網路（多層神經網路、注意力／自注意力處理長距離依賴）、訓練數據處理（清洗、標記化、向量化）、推理機制（溫度、Top-k、核採樣）。溫度低→保守，高→創意；核採樣＝累積機率達閾值（如 0.9）。主要挑戰含計算資源、硬體限制、準確性、AI 幻覺、偏見與安全。
⚠️ 易混淆Top-k vs 核採樣（Top-p）：Top-k 固定取「前 k 名」；Top-p 取「累積機率到 p 為止」的那群，候選數量不固定。標記化 vs 向量化：前者是「切」，後者是「轉數字」。溫度不會讓模型「更聰明」，只改變選字的冒險程度；調低溫度也不能根除幻覺。
🚀 延伸與新進展考試範圍外
  • 少樣本提示（Few-shot prompting）（2020）：GPT-3 論文展示只要在提示中給幾個範例，模型就能照樣完成新任務，不必重新訓練。這是「透過提示詞進行可控生成」的基礎技巧；對照是不給範例的 Zero-shot。
  • 思維鏈（Chain-of-Thought, CoT）（2022）：Google 研究者提出在提示中示範「逐步推理」，可明顯改善數學與邏輯題表現；後續衍生自我一致性（Self-consistency，2022，多次推理取多數答案）與思維樹（Tree of Thoughts, ToT，2023，同時探索多條推理路徑再比較）。
  • 推理模型（Reasoning models）（2024）：OpenAI 於 2024 年 9 月發表 o1-preview，以大規模強化學習訓練模型在回答前先產生內部思考過程，且「思考越久、表現越好」。差別在於：CoT 是「使用者在提示裡要求逐步想」，推理模型則是「訓練時就學會自己先想」。
  • 專家混合架構（Mixture of Experts, MoE）（2023）：如 Mistral AI 於 2023 年 12 月以 Apache 2.0 授權釋出的 Mixtral 8x7B，每次只啟用部分「專家」子網路，總參數大但每次計算量較小，是指引「模型效率」方向的代表做法之一。
  • 情境工程（Context engineering）（2025）：2025 年中由 Shopify 執行長 Tobi Lütke、Andrej Karpathy 等人推廣的說法：在真實 AI 應用中，比起把一句提示寫漂亮，更關鍵的是「把對的資訊放進模型的上下文」，包括系統指示、工具說明、記憶、檢索到的文件與使用者輸入。可視為提示工程的進化版。

AI 訓練師AI Trainer

技術突破與發展方向 完整教材 ↗

💬 白話說生成式 AI 的家族史：GAN 讓 AI 第一次畫出逼真的臉；VAE、流式模型提供比較穩定、可算機率的生成；Transformer 讓 GPT 寫出流暢文章，也撐起 DALL-E、Stable Diffusion 等多模態生成；預訓練＋微調＋RLHF 讓模型從「會接龍」變成「會聽話」；vLLM、壓縮量化讓模型跑得快、跑得省，甚至上手機。
🧠 記憶口訣對抗畫臉、Transformer 寫字、擴散去噪、人類回饋教乖
GAN＝對抗；擴散模型＝從雜訊一步步「去噪」還原出圖；RLHF＝用人類偏好當獎勵，讓模型回答更符合人意。

📖 名詞小辭典

流式生成模型Flow-based Generative Model
用一連串可逆轉換，把簡單分布變成複雜資料分布，能精確計算機率。例：像把一團麵糰經過可還原的揉捏步驟，變成特定形狀。
GPTGenerative Pre-trained Transformer
OpenAI 的「生成式預訓練 Transformer」模型系列，以預測下一個 Token 的方式生成文字。例：GPT-4 提升了理解與生成準確度。
大型語言模型Large Language Model, LLM
以海量文字預訓練、參數規模龐大的語言模型。例：GPT 系列、Claude、Gemini、Llama。
參數規模Parameter Scale
模型內可學習數值的數量，常以「億、十億（B）」計。例：「7B 模型」＝約 70 億個參數。
Stable DiffusionStable Diffusion
以擴散模型為核心、開放權重的文字生成圖像模型。例：可在自家電腦上生成產品情境圖。
MidjourneyMidjourney
以藝術風格著稱的商業圖像生成服務。例：生成概念美術、海報草圖。
擴散模型Diffusion Model
訓練時學「把加了雜訊的圖還原」，生成時從純雜訊一步步去噪得到新圖。例：像從滿是雪花的電視畫面慢慢調出清楚影像。
預訓練Pre-training
先用海量通用資料訓練模型的基礎能力。例：先讀遍網路文章學會語言。
微調Fine-tuning
在預訓練模型上，用特定任務或領域資料再訓練，調整其行為或知識。例：用公司客服紀錄微調，讓語氣符合品牌。
少樣本學習Few-shot Learning
只靠少量範例就能學會或完成新任務。例：給三則範例回覆，模型就照格式回覆第四則。
提示工程Prompt Engineering
設計與優化提示詞，以提高生成品質與可控性的方法。例：指定角色、格式、字數、範例與限制條件。
人類回饋強化學習Reinforcement Learning from Human Feedback, RLHF
由人類比較並評分模型回答，訓練出「偏好模型」作為獎勵，再用強化學習讓模型往人類偏好的方向調整。例：標註員選出兩個回答中較有幫助、較安全的那個。
vLLMvLLM
開源的大型語言模型推理與服務引擎，以高效記憶體管理提升吞吐量。例：同一台 GPU 伺服器可同時回應更多使用者。
邊緣計算Edge Computing
在資料產生地附近（裝置端、工廠現場）運算，而非全部送到雲端。例：工廠相機內建 AI 即時檢測瑕疵。
Hugging FaceHugging Face
全球最大的開源模型與資料集分享平台之一，提供模型庫與工具套件。例：下載開源模型、在 Spaces 上試玩示範應用。
開放原始碼Open Source
原始碼公開、允許依授權使用與修改的軟體。例：社群共同改良開源模型工具。
📌 考試重點技術突破：GAN（高品質圖像）、VAE 與流式模型（穩定性、機率生成）、Transformer 與自注意力（GPT、DALL-E、Stable Diffusion）、預訓練與微調（少樣本學習、提示工程、RLHF）、高效推理與模型壓縮（vLLM，適用邊緣計算與行動裝置）。工具方向：A 模型規模與能力提升、B 輕量化與個人化、C 深層學習架構改進（GAN 與擴散模型融合）；開源社群如 Hugging Face。
⚠️ 易混淆RLHF ≠ 微調資料：RLHF 用的是「人類對回答的偏好」當獎勵訊號，而一般監督式微調（SFT）用的是「標準答案範例」。預訓練 vs 微調：前者打底、資料海量通用；後者加工、資料少而專。
🚀 延伸與新進展考試範圍外
  • LoRA（低秩適應）（2021）：微調時凍結原模型，只訓練少量外掛的小矩陣，大幅降低微調所需記憶體與儲存；屬「參數高效微調」（Parameter-Efficient Fine-Tuning, PEFT）的代表。
  • QLoRA（2023）：Dettmers 等人提出，把基礎模型量化成 4 位元後再做 LoRA，論文示範單張 48GB GPU 即可微調 650 億參數模型。結合指引中的「量化」與「微調」兩個概念。
  • DPO（直接偏好最佳化）（2023）：Stanford 團隊提出，直接用人類偏好資料調整模型，不必另訓獎勵模型、也不必跑強化學習，比 RLHF 流程簡單，成為常見的對齊方法之一。
  • PagedAttention／vLLM 論文（2023）：發表於 SOSP 2023，借用作業系統「分頁」概念管理生成時的快取記憶體，減少浪費、提高同時服務量；這就是指引所提 vLLM 的核心技術。同類加速技術還有 FlashAttention（2022），減少注意力計算的記憶體搬運。
  • 擴散＋Transformer 的融合（2024）：Stable Diffusion 3 論文（2024 年 3 月）以 Transformer 架構（MMDiT）取代傳統卷積網路骨幹，並採用整流（rectified flow）訓練；同年 2 月 OpenAI 發表文字生成影片模型 Sora。這是指引「架構改進、多模態融合」方向的實例。
  • 推理能力靠強化學習（2025）：DeepSeek-R1（2025 年 1 月）公開以強化學習培養推理能力的做法並釋出權重；強化學習的角色從 RLHF 的「教乖」延伸到「教會思考」。

🚀 延伸與新進展考試範圍外
  • 檢索增強生成（Retrieval-Augmented Generation, RAG）（2020）：先從外部知識庫檢索相關文件，再交給模型根據文件回答，可引用來源、知識更新不必重訓。這是「領域知識整合」最常見的企業做法。
  • RAG 的進化：混合檢索與重排序（2019 起）：同時用關鍵字檢索（如 BM25）與向量語意檢索，再用 BERT 類的重排序模型（2019 年 Nogueira 與 Cho 提出以 BERT 做段落重排）挑出最相關段落，比單用向量搜尋更準。
  • GraphRAG（2024）：Microsoft Research 於 2024 年 4 月提出，先用 LLM 從文件抽出實體與關係建成知識圖譜、分群摘要，擅長回答「整批資料的主要主題是什麼」這類全域問題，彌補一般 RAG 只能找片段的弱點。
  • Agentic RAG（2025）：2025 年 1 月的綜述論文整理此方向：由 AI Agent 主導檢索，會自行判斷資訊是否足夠、改寫查詢、多輪檢索與反思，取代「固定只查一次」的傳統 RAG 流程。
  • Model Context Protocol（MCP）（2024）：Anthropic 於 2024 年 11 月提出的開放標準，讓 AI 應用用統一方式連接外部工具、資料源與 API，被稱為 AI 的「USB-C 介面」；2025 年 12 月捐贈給 Linux 基金會旗下的 Agentic AI Foundation。它對應指引「生態系統建構」與「API、外掛整合」趨勢。
  • 多模態影音生成（2024–2025）：OpenAI 於 2024 年 2 月發表文字生成影片的 Sora；Google 於 2025 年 5 月發表可同步生成對白、音效的 Veo 3。指引「影音內容生成」趨勢已從剪輯特效走到直接生成有聲影片，也讓深偽風險上升。
  • 小型模型與本地部署（2024）：Phi-3-mini 等小型語言模型可在筆電甚至手機執行，配合量化技術，讓「本地部署選項」對中小企業也變得可行。

肆、生成式AI 導入評估

本章回答「要不要導入、準備好了沒、怎麼一步步來」。導入不只是技術升級，而是營運模式與策略的革新。考題常以情境出現：「企業導入的第一步是什麼？」「哪個項目應優先試點？」

五大評估面向 完整教材 ↗

💬 白話說導入評估就像搬新家前的健檢：先問「為什麼要搬」（需求與痛點）、「錢和家具夠不夠」（資源、資料、硬體、人才）、「要一次搬完還是分批」（分階段策略）、「家人能不能適應新環境」（員工技能與文化）、「搬家路上會出什麼事」（風險）。其中最容易被忽略的是資料：生成式 AI 很吃資料品質，垃圾進、垃圾出。
🧠 記憶口訣需、資、策、人、險
五大評估面向：需求與現狀、資源與基礎設施、導入策略（分階段）、員工技能與文化、風險評估與管理。

📖 名詞小辭典

痛點識別Pain Point Identification
找出流程中最困擾、最耗成本的問題（流程瓶頸、資源失衡、決策不足）。例：客服每天花三小時回覆相同的退貨問題。
應用場景分析Use Case Analysis
評估 AI 用在哪些情境能提升品質、縮短週期或優化客戶體驗。例：比較「自動寫週報」與「客服回覆草稿」哪個效益大。
技術對接性Technical Compatibility
新 AI 方案與現有系統、資料格式能否順利銜接。例：AI 工具能否讀取公司文件管理系統的檔案。
數據完整性Data Integrity / Completeness
資料是否齊全、正確、一致，未缺漏或被不當修改。例：產品資料表每筆都有規格、價格與更新日期。
數據整合Data Integration
把分散在不同系統的資料彙整成一致可用的形式。例：把門市 POS 與電商訂單整合成同一份顧客資料。
系統可擴展性Scalability
使用量或範圍擴大時，系統能否跟著擴充而不崩潰。例：從一個部門 20 人用，擴大到全公司 2000 人用。
試點應用Pilot
先在小範圍、可控條件下試行，驗證效果再擴大。例：先讓一個門市試用 AI 排班一個月。
模型偏誤Model Bias
模型輸出系統性偏向某些結果或族群，屬技術風險。例：履歷篩選模型偏好特定學校。
資源調度風險Resource Allocation Risk
人力、預算、算力分配不當造成專案延誤或失敗的風險。例：GPU 資源被其他專案占用，導致上線延期。
📌 考試重點五大面向的內容要能對應：資源與基礎設施＝技術人才、數據品質與基礎（完整性、清洗整合）、硬體與系統架構、可擴展性；導入策略＝試點→階段性擴展→長期目標→持續優化回饋。歷屆高頻：企業導入的第一步是設定明確、可量化的經營目標，而非先買軟硬體。

導入策略與實施建議 完整教材 ↗

💬 白話說導入順序像減重計畫：先挑「容易做到又馬上看得到成效」的（例如每天少喝一杯含糖飲料），建立信心；需要大量資源又短期看不到效果的（例如全馬訓練）先往後排。企業也是：先試點驗證（初始）、再跨部門推廣（成長）、最後全面整合、創新領先（成熟）。
🧠 記憶口訣先易後難、先快後慢；試點、推廣、領先
優先級：業務影響大＋技術難度低＋快速見效者優先；三階段：初始（試點與驗證）→成長（技術推廣與整合）→成熟（全面整合與創新領先）。

低技術難度、短期即可看到效益的項目，用來建立信心與支持。例：用 AI 自動整理會議紀錄。
核心價值Core Value
企業最主要、最能創造競爭力的價值來源。例：精品咖啡店的核心價值是風味與服務體驗。
差異化競爭Differentiation
以別人難以模仿的特色取得競爭優勢。例：用 AI 提供競爭對手做不到的即時客製報價。
滾動式調整Rolling Adjustment
依市場與執行狀況定期檢討並修正計畫。例：每季重新評估 AI 專案清單與預算。
跨部門合作Cross-functional Collaboration
業務、資訊、法務等不同部門共同推動專案。例：客服部提出需求、資訊部建置、法務審查個資。
📌 考試重點目標設定考量兩件事：公司人力的業務影響（能否創造核心價值、提升效率、滿意度或顯著降成本）與技術實現的實施難度（低難度、快見效者優先，資源高且短期難見效者延後）。三階段：初始＝低成本、風險可控的小範圍試點；成長＝跨部門推廣到多個業務環節；成熟＝創新應用、差異化競爭、依市場滾動調整。

提供 AI 建置、整合、顧問服務的外部廠商。例：協助企業建置內部知識庫問答系統的廠商。
學習曲線Learning Curve
從不會到熟練所需的時間與努力。引進外部專家可縮短學習曲線。例：有顧問帶，三個月就能上線；自己摸索可能要一年。
📌 考試重點AI 導入「不只是引進工具」，必須深入了解企業業務結構、找出最能受益的環節；技術人才培養是生成式 AI 導入的核心挑戰之一；解法是內部培訓（含依業務場景選模型、系統規劃集成）＋外部專家合作，採內外結合。
🚀 延伸與新進展考試範圍外
  • AI 素養義務（2025）：EU AI Act 第 4 條自 2025 年 2 月 2 日起要求提供者與部署者採取措施確保員工具備足夠 AI 素養；與歐盟有業務往來的台灣企業，教育訓練規劃可參考此要求。
  • 台灣《人工智慧基本法》提到人才與勞動（2026）：2026 年 1 月公布施行，條文要求政府保障勞工權益、彌平 AI 發展造成的技能落差，並輔導因 AI 失業者，顯示「人才培養與轉型」已是國家政策層級議題。

伍、生成式AI 導入規劃

本章是全科最常出題的一章：四階段導入流程（準備→設計→驗證 POC→實施／營運）以及每一階段做什麼，還有模型訓練、驗證指標、監控與 ROI 計算的名詞。

四階段導入流程 完整教材 ↗

💬 白話說把導入 AI 想成開一家新分店：
① 準備＝選地點、選賣什麼（挑 AI 應用方案）；
② 設計＝畫藍圖、算預算（確認 AI 生成規格）；
③ 驗證 POC＝先試營運一個月看生意（驗證 AI 效果、算 ROI）；
④ 實施／營運＝正式開幕並持續改善，成功了再複製到其他分店（持續發揮價值）。
🧠 記憶口訣挑、規、驗、營
準備＝挑方案；設計＝定規格；POC＝驗效果；實施＝營運持續發揮價值。

📖 名詞小辭典

概念驗證Proof of Concept, POC
以小規模實驗測試模型在真實業務中的準確度、效率與融合度，並量化投入產出（ROI、回收週期），作為擴大導入的依據。例：先讓 AI 處理一個月的客服信件，比較回覆時間與滿意度。
關鍵績效指標Key Performance Indicator, KPI
可量化、用來追蹤目標達成程度的指標。例：客服平均處理時間從 8 分鐘降到 5 分鐘。
回收週期Payback Period
累積效益回收初始投資所需的時間。例：投入 20 萬、每月省 2.9 萬，約 7 個月回本。
模型監控Model Monitoring
上線後持續追蹤模型表現與輸入資料變化。例：每週檢查 AI 回覆被客服修改的比例。
重新訓練Retraining
用新資料再訓練模型，使其適應最新狀況。例：新產品上市後，用新 FAQ 更新模型或知識庫。
AI 價值擴散Scaling AI Value
把成功的單點 AI 應用推廣到全企業。例：北區客服成功後，複製到中南區與電商客服。
階段核心任務關鍵產出
（1）準備挑選 AI 應用方案：掌握企業課題、檢視方案與資源、確定優先順序候選方案與優先清單
（2）設計確認 AI 生成規格：最終目標、數據狀態、使用情境、導入成本KPI、資料與成本規劃
（3）驗證 POC驗證 AI 效果：模型開發至部署、導入實務流程、ROI 計算效果驗證與投資效益
（4）實施／營運持續發揮價值：專案落地、模型監控與重新訓練、價值擴散常態營運與推廣
📌 考試重點四階段的順序與名稱必背：準備（挑選 AI 應用方案）→ 設計（確認 AI 生成規格）→ 驗證 POC（驗證 AI 效果）→ 實施／營運（持續發揮價值）。ROI 計算放在 POC 階段；模型監控與重新訓練屬實施／營運階段。規劃初期先明確經營目標（市場定位、核心產品價值、長期成長策略）。
⚠️ 易混淆「估算導入成本」屬設計階段；「ROI 計算」屬POC 階段——一個是事前估算花多少，一個是驗證後算值不值得。「試點運行」出現在 POC 階段的「導入實務運作流程」五步驟中。
🚀 延伸與新進展考試範圍外
  • 評估驅動開發（2023）：生成式 AI 的輸出沒有唯一標準答案，業界常在 POC 一開始就建立「評估集」（代表性問題＋期望回答＋評分標準），每次改提示、換模型、調 RAG 都重跑一遍；評分常結合人工與「LLM 當評審」（LLM-as-a-judge，見 5-4）。這讓 POC 的「驗證 AI 效果」可重複、可比較。

準備階段 完整教材 ↗

💬 白話說準備階段像看醫生前先寫症狀清單：先弄清楚哪裡痛（掌握企業課題）、家裡有什麼藥和預算（檢視方案與資源）、先治哪個症狀（優先順序）。最好的第一個 AI 專案通常是重複性高、規則清楚、標準化的工作，例如客服常見問答、內部資料檢索、報表生成。

AI 方案的三大來源：買現成產品、用開源自行建置、請廠商量身開發。例：訂閱 AI 會議記錄服務 vs 自架開源模型 vs 委外開發專屬系統。
軟體許可Software License
使用軟體的授權與費用條件。例：按使用者人數計費的年度授權。

不在報價單上、但實際會發生的成本。例：資料整理人力、員工學習期間的效率下降。
專案管理架構Project Management Structure
明定專案負責人、角色分工與進度控管方式。例：指定專案經理、每兩週開進度會議。
📌 考試重點理想的優先導入候選：具重複性、規則性、標準化的工作（數據處理、報表生成、客服查詢）；從簡單且可行的核心專案開始（如客服回應、內部資料檢索）。生成式 AI 必要性要檢視數據完整性、準確性、格式一致性與歷史資料豐富度、技術基礎設施與人力技能。優先順序綜合商業價值、技術可行性與成熟度、資源與成本、長期戰略目標。
🚀 延伸與新進展考試範圍外
  • 方案選擇多了「開放權重模型」選項（2024–2025）：除商業 API 外，Phi-3（2024）、DeepSeek-R1（2025，MIT 授權）等開放權重模型可自行部署，資料不出公司、可微調；代價是要自備算力、維運人力與安全評估。準備階段比較方案時，可把「API 服務／開放權重自建／混合」三種模式並列評估。

數據標記Data Labeling / Annotation
為資料加上正確答案或類別，供模型學習或評估。例：把客訴信件標上「物流」「品質」「退款」。
數據流程Data Pipeline
自動化收集、清理、轉換、更新資料的流程。例：每天凌晨自動把新訂單整理進分析資料庫。
預測性維護Predictive Maintenance
依設備感測資料預測故障，在壞掉前安排保養。例：馬達震動異常時提前排程更換軸承。
部署策略Deployment Strategy
規劃模型放在哪裡（雲端、地端、邊緣）、如何上線與更新。例：先內部試用，再逐步開放給客戶。
數據偏差Data Bias
資料來源單一或不具代表性，使模型學到偏頗結果；收集多來源數據可降低。例：只用北部門市資料訓練，模型不懂南部顧客習慣。
📌 考試重點設計階段四步：A 讓 AI 方案與公司策略一致、定短長期目標、制定可量化 KPI；B 數據品質、準確性與多樣性直接影響學習，收集多來源以減少偏差、清理與標記、建立持續更新的數據流程避免模型因過時數據失效；C 依業務規劃使用情境（自動化客服、數據分析、預測性維護）並規劃部署策略；D 成本含技術開發（建構、測試、部署、再訓練）、硬體與雲端、人員培訓、軟體維護升級。
🚀 延伸與新進展考試範圍外
  • 規格裡寫明「輸出格式」（2024）：結構化輸出（Structured Outputs，2024）讓模型保證輸出符合指定 JSON 結構；設計階段可直接把「欄位、型別、必填」寫進規格，方便後端系統承接與自動驗證。
  • 情境工程納入設計（2025）：使用情境確認後，進一步規劃「模型每次要看到哪些資訊」：系統指示、相關文件（RAG）、可用工具（如透過 MCP）、對話記憶與權限範圍，這直接影響品質、成本與資安。

驗證 POC 階段 完整教材 ↗

💬 白話說POC 階段就是考駕照：
・模型開發＝選車（自迴歸、自編碼器、擴散、Transformer），並設定好教練的教法（損失函數、優化器、學習率、批次、週期）。
・防止過擬合＝不要只會背考古題（過擬合），也不能什麼都沒學會（欠擬合）；所以要用交叉驗證、正則化、Dropout、早停。
・驗證效能＝筆試（BLEU、ROUGE、Perplexity 等自動指標）＋路考（人工檢查）＋惡劣天候測試（壓力與邊界）＋公平性檢查＋兩台車比一比（A/B 測試）。
・導入實務流程＝拿到駕照後先在社區小路開（試點運行），並上課（員工培訓）、持續改進、評估後推廣。
🧠 記憶口訣BLEU 翻譯看準、ROUGE 摘要看全、困惑度越低越順
BLEU 偏重精確率（生成的詞有多少出現在參考答案），常用於機器翻譯；ROUGE 偏重召回率（參考答案的詞有多少被涵蓋），常用於摘要；Perplexity（困惑度）越低，代表模型對文字越「不困惑」、語言越流暢。
導入實務五步：整、試、訓、改、推（業務流程整合、試點運行、員工培訓、持續改進、效益評估與推廣）。

📖 名詞小辭典

自迴歸模型Autoregressive Model
依前面已產生的內容，一個接一個預測下一個元素。例：GPT 逐字接龍寫出整段文章。
自編碼器Autoencoder
先把輸入壓縮成精簡表示，再還原回原貌的神經網路；VAE 是其機率版本。例：把圖片壓成少量數字再還原，用來去雜訊或偵測異常。
基於 Transformer 的多層神經網路Transformer-based Neural Network
以 Transformer 區塊堆疊而成的深度網路，是現今 LLM 主流架構。例：數十層 Transformer 堆成的大型語言模型。
創造性／生成控制能力Creativity / Generation Control
生成內容的新穎多樣程度／依需求控制輸出的能力；需調整生成參數平衡兩者。例：行銷文案要創意，法規回覆要精確可控。
損失函數Loss Function
衡量模型預測與正確答案差距的公式，訓練目標是讓它越小越好。例：猜錯越離譜，扣分越多。
交叉熵損失Cross-Entropy Loss
衡量預測機率分布與正確答案差距的損失函數，自迴歸語言模型常用。例：正確下一個字是「貓」，模型給「貓」的機率越高，損失越小。
優化器Optimizer
依損失決定如何調整模型參數的演算法。例：AdamW、LAMB。
AdamWAdam with decoupled Weight decay
Adam 優化器的改良版，把權重衰減（一種正則化）與梯度更新分開處理，訓練大型模型常用。例：多數 Transformer 訓練預設使用 AdamW。
LAMBLayer-wise Adaptive Moments optimizer for Batch training
為「超大批次訓練」設計的優化器，可逐層調整更新幅度，加速大規模訓練。例：用很大的 Batch Size 平行訓練語言模型。
學習率Learning Rate
每次調整參數的步伐大小；太大會暴衝、太小學很慢。例：下山時每步跨多大。
批次大小Batch Size
每次更新參數時一起計算的樣本數。例：一次看 32 篇文章再調整一次。
訓練週期數Epochs
整份訓練資料被完整看過幾輪。例：課本從頭到尾讀了 3 遍＝3 個 epoch。
超參數Hyperparameter
訓練前由人設定、不由模型自己學的參數，如學習率、批次大小。例：烤蛋糕的溫度與時間。
網格搜索Grid Search
把超參數的候選值排成網格，逐一組合試驗找最佳者。例：學習率 3 種 × 批次 3 種＝試 9 組。
交叉驗證Cross Validation
把資料輪流切成訓練與驗證部分多次評估，結果更可靠，降低過擬合／欠擬合風險。例：資料分 5 份，輪流拿 1 份當驗證、做 5 次取平均。
訓練集／驗證集／測試集Training / Validation / Test Set
分別用來學習、調參與最終評估；測試集要留到最後才用，確保泛化能力。例：課本（訓練）、模擬考（驗證）、正式考試（測試）。
泛化能力Generalization
模型面對沒看過的新資料仍表現良好的能力。例：沒背過的題目也會解。
過擬合Overfitting
模型把訓練資料背得太熟（連雜訊都學），遇到新資料表現差。例：只會背考古題答案，題目換個數字就不會。
欠擬合Underfitting
模型太簡單或學太少，連訓練資料都表現不好。例：只讀了目錄就上考場。
L2 正則化L2 Regularization
在損失中加入「參數平方和」的懲罰，讓參數不要太大，降低過擬合。例：限制模型不要過度依賴少數特徵。
Dropout（隨機丟棄）Dropout
訓練時隨機暫時關閉部分神經元，迫使模型不依賴特定路徑。例：球隊練習時隨機讓主力休息，逼其他人也練強。
早停策略Early Stopping
驗證表現不再進步時就停止訓練，避免過擬合。例：模擬考成績開始下滑就不再狂刷同一本題庫。
混合精度訓練Mixed Precision Training
部分計算用較低精度（如 16 位元）、關鍵部分保留高精度，以減少資源消耗並加速訓練。例：草稿用鉛筆、定稿再用鋼筆。
生成準確度Accuracy
生成或預測結果正確的比例。例：100 題答對 92 題＝92%。
語義連貫性Semantic Coherence
生成內容前後意思是否一致、通順合理。例：前段說「下雨」，後段不該突然說「豔陽高照所以帶傘」。
生成多樣性Diversity
生成內容是否豐富多變而不重複。例：十則文案不要都是同一句型。
模型剪枝Pruning
移除對結果影響小的參數或連結，讓模型變小變快。例：修剪盆栽多餘的枝葉。
BLEUBilingual Evaluation Understudy
比較生成文字與參考答案的詞組重疊程度，偏重精確率，常用於機器翻譯。例：AI 翻譯與專業譯文用詞越相同，分數越高。
ROUGERecall-Oriented Understudy for Gisting Evaluation
以召回率為導向，衡量參考答案中的內容有多少被生成文字涵蓋，常用於摘要。例：AI 摘要是否涵蓋人工摘要中的重點詞。
困惑度Perplexity
衡量語言模型對文字的預測不確定性，數值越低表示越能預測、語言越流暢。例：讀到「台北 101 是一棟」時，模型很確定下一個詞是「大樓」。
邊界檢查Boundary Testing
用稀有、極端或異常輸入檢測系統穩定性。例：輸入空白、超長文字、混雜表情符號的提問。
敏感性與公平性檢查Sensitivity & Fairness Check
分析輸入小變化對輸出的影響，並檢測對特定群體是否不公平。例：履歷只改姓名性別，評分是否改變。
A/B 測試A/B Testing
把使用者分組，同時比較兩個版本的實際成效。例：一半客戶收到舊版回覆、一半收到新版，比較滿意度。
📌 考試重點模型選擇常見四類：自迴歸、自編碼器、擴散、基於 Transformer 的多層神經網路，需考慮創造性與生成控制能力並結合提示工程。訓練：交叉熵損失、AdamW／LAMB、L2／Dropout／早停防過擬合、混合精度省資源、剪枝與量化、遷移學習。驗證六步：設定基準（BLEU、ROUGE、Perplexity）→自動化與批量測試→主觀人工檢查→壓力與邊界檢查→敏感性與公平性檢查→A/B 測試與線上驗證。導入實務五步：業務流程整合→試點運行→員工培訓→持續改進→效益評估與推廣。
⚠️ 易混淆過擬合 vs 欠擬合：訓練好、測試差＝過擬合；兩者都差＝欠擬合。過擬合 vs 數據漂移：過擬合是訓練當下就泛化差；漂移是上線後資料分布隨時間改變（見 5-5）。Perplexity 越低越好，BLEU／ROUGE 越高越好。網格搜索是調超參數，交叉驗證是評估方式，兩者常搭配但不同。
🚀 延伸與新進展考試範圍外
  • LLM 當評審（LLM-as-a-judge）（2023）：Zheng 等人 2023 年的 MT-Bench／Chatbot Arena 研究顯示，強大的 LLM 評分與人類偏好的一致程度可達到人與人之間的一致水準，同時指出位置偏誤（偏好排在前面的答案）、冗長偏誤（偏好較長答案）、自我偏好等問題。它補足 BLEU／ROUGE 只看字面重疊、不懂語意的弱點，但重要場景仍需人工抽查。
  • 參數高效微調（PEFT）：LoRA／QLoRA（2021／2023）：POC 若需要微調，業界多用 LoRA 或 QLoRA 只訓練少量外掛參數，成本遠低於全量微調，也方便保存多個任務版本、隨時切換。
  • RAG 的專屬評估（2024–2025）：導入 RAG 時，除了看最終答案，也要分開評估「檢索有沒有找對文件」與「回答是否忠於文件（不憑空捏造）」；這兩項常用 LLM-as-a-judge 搭配人工標註來衡量。

實施/營運階段 完整教材 ↗

💬 白話說模型上線不是終點，而像養一盆植物：環境會變（季節＝數據漂移），要定期看葉子（監控 Accuracy、Recall、錯誤率），狀況變差就換土施肥（重新訓練），最好裝自動澆水系統（自動化重新訓練管道，效能低於警戒值就自動觸發）。養成功了再分株給其他部門（AI 價值擴散）。
🧠 記憶口訣落地、監控、擴散；漂移就重訓
A 專案落地 → B 模型監控與重新訓練 → C AI 價值擴散；數據漂移→更新訓練資料／觸發 Retraining Pipeline。

📖 名詞小辭典

準確率Accuracy
所有預測中預測正確的比例。例：1000 封信分類正確 950 封＝95%。
召回率Recall
所有真正的正例中，被模型成功找出的比例；重視「不要漏掉」。例：100 筆真的詐騙交易抓到 90 筆＝召回率 90%。
預測錯誤率Error Rate
預測錯誤的比例，等於 1 − 準確率。例：準確率 95%，錯誤率就是 5%。
數據漂移Data Drift
輸入資料的分布隨時間改變（業務場景或用戶行為改變），導致模型準確性下降。例：疫情後網購比例暴增，原本的需求預測模型失準。
自動化重新訓練管道Retraining Pipeline
自動收集新資料、重新訓練、測試並部署模型的流程，效能達警戒值時自動觸發。例：準確率連續一週低於 90% 就自動啟動重訓。
跨職能支持體系Cross-functional Support
由業務、IT、資料、法務等組成的支援團隊，協助專案長期運作。例：每月由各部門代表檢討 AI 使用狀況。
創新獎勵機制Innovation Incentives
獎勵提出或推廣 AI 應用的員工，促進良性循環。例：年度 AI 應用提案競賽。
📌 考試重點監控指標：準確率（Accuracy）、召回率（Recall）、預測錯誤率（Error Rate）；定期檢查數據漂移；建構自動化重新訓練管道於效能達警戒值時自動觸發。AI 價值擴散：由單點推廣至全企業、分享成功案例、設立創新獎勵。
⚠️ 易混淆準確率 vs 召回率：資料不平衡時（例如詐騙只佔 1%），模型全猜「不是詐騙」也有 99% 準確率，但召回率是 0；所以「不能漏」的任務要看召回率。
🚀 延伸與新進展考試範圍外
  • 模型版本固定與供應商更版風險（2023）：使用雲端 API 時，供應商會更新或退役模型；OpenAI 於 2023 年 6 月起提供可指定日期版本的模型快照，讓輸出行為在版本固定期間保持穩定。營運階段要把「供應商換版」當成另一種漂移：換版前先用評估集回歸測試。
  • 生成式 AI 的監控項目更多元（2024–2025）：除了準確率，常見還會監控幻覺率、被人工修改的比例、拒答率、不當內容攔截次數、回應延遲與 Token 用量（成本），並保留紀錄以便稽核。

ROI 計算方式 完整教材 ↗

💬 白話說ROI 分析就是老闆最在乎的那張表：花了什麼錢（成本：開發部署、設備、維護、人力）、賺回什麼（直接：營收、滿意度、市場；間接：流程效率、人力最佳化）、多久回本（回本時間）、把未來的錢折成今天的價值還划不划算（NPV、IRR），以及「萬一情況變差」的試算（敏感性分析）。
🧠 記憶口訣本、益、指、險
成本構成、收益分析、財務指標（回本時間、NPV、IRR）、風險模擬（敏感性分析）。NPV＞0 划算；IRR＞資金成本划算。

📖 名詞小辭典

淨現值Net Present Value, NPV
把未來各期現金流以折現率換算成今天的價值後，再減去初始投資；大於 0 代表划算。例：今天投入 100 萬，未來效益折現後值 130 萬，NPV＝30 萬。
內部報酬率Internal Rate of Return, IRR
讓 NPV 剛好等於 0 的折現率，可想成專案的「年化報酬率」；高於資金成本才值得投資。例：IRR 18%，公司借錢成本 5%，值得做。
回本時間Payback Period
累積淨效益回收初始投資所需時間。例：整合成本 20 萬、每月淨省 29,040 元，約 7 個月回本。
敏感性分析Sensitivity Analysis
改變某個關鍵假設（市場、業務量、成本），觀察結果變化有多大。例：若 API 用量多 50%，回本時間會從 7 個月變成幾個月？
折現率Discount Rate
把未來的錢換算成現在價值時使用的比率，反映資金成本與風險。例：明年的 100 元，以 5% 折現約等於今天的 95 元。
公式NPV ＝ Σ［第 t 期淨現金流 ÷（1＋折現率）t］− 初始投資　　ROI ＝（效益 − 成本）÷ 成本
📌 考試重點四個層面：成本構成（技術開發與部署、設備購置、基礎設施維護、專業人力）、收益分析（直接：營收、滿意度、市場擴展；間接：流程效率、人力最佳化）、財務指標（回本時間、NPV、IRR）、風險模擬（敏感性分析）。歷屆常出回收期計算：回收期 ≈ 導入成本 ÷ 每期淨節省。
⚠️ 易混淆NPV 是「金額」、IRR 是「比率」；回本時間沒考慮貨幣時間價值，NPV／IRR 有。敏感性分析屬「風險模擬」，不是「財務指標」。
🚀 延伸與新進展考試範圍外
  • Token 計費讓成本變成「變動成本」（2023 起）：雲端 LLM API 多以輸入／輸出 Token 計費，成本隨用量浮動；推理模型（2024 起）在回答前會產生額外的思考內容，通常也計入用量。因此 ROI 試算應做「用量情境」的敏感性分析，而不只用單一平均值。
  • 降低變動成本的手段（2024–2025）：依任務難度分流（簡單問題給小模型、難題給大模型）、批量處理、縮短提示與檢索內容、對重複的前置內容使用快取等，都是近年常見的成本優化手法。

風險管理重點 完整教材 ↗

💬 白話說生成式 AI 的風險管理像開餐廳的食安四件事：食材來源合法（遵守法律、審查資料授權）、客人資料不外洩（資料隱私）、不歧視任何客人（降低倫理偏見）、出菜前有人試吃把關（建立審核機制）。任何一件出事，都會傷到資安、品牌與法律責任。
🧠 記憶口訣私、偏、法、審
確保資料隱私（加密、匿名化、權限）、降低倫理偏見（多樣化資料＋公平性測試）、遵守法律規範（審查資料來源授權）、建立審核機制（監控審查生成內容）。

📖 名詞小辭典

敏感資訊Sensitive Information
外洩會造成個人或企業傷害的資料，如個資、營業秘密、財務資料。例：客戶身分證號、未公開的產品設計。
公平性測試Fairness Testing
檢查模型對不同群體的結果是否有不合理差異。例：比較不同年齡層客戶的貸款審核建議。
內容審核機制Content Moderation / Review
對生成內容進行監控與審查，避免發布不適當內容。例：AI 產生的新聞稿須經公關主管核可才發布。
品牌聲譽風險Reputational Risk
因不當事件損及企業形象與信任的風險。例：客服機器人回覆歧視言論被截圖瘋傳。
📌 考試重點常見風險三大類：資料隱私與安全、倫理偏見、法律合規，影響資訊安全、品牌聲譽與法律責任。四項重點：確保資料隱私、降低倫理偏見、遵守法律規範、建立審核機制。
🚀 延伸與新進展考試範圍外
  • OWASP LLM 應用十大風險（2025 版）（2025）：可作為四項重點之外的技術檢查表，特別是指引較少提到的提示注入、系統提示洩漏、過度代理權（給 AI 太多權限，例如讓客服機器人能直接退款）與無上限資源消耗（被濫用導致費用暴增）。
  • AI Agent 讓風險從「說錯話」升級到「做錯事」（2025）：能呼叫工具的 Agent 若被誤導，可能刪檔、寄信、下單。常見對策是最小權限、高風險動作需人工確認、操作留存紀錄，呼應指引「建立審核機制」。

資料隱私與安全 完整教材 ↗

💬 白話說模型讀過大量資料，有時會「說溜嘴」把訓練資料原文吐出來（訓練數據洩漏）；壞人也會拆解模型推敲它學了什麼（反向工程）、一直問想拼湊出敏感資料（提示詞攻擊）、或設計陷阱輸入騙它做壞事（對抗性攻擊）。防守三招：確認身分與權限、資料加密、差分隱私（在資料或結果中加入精心控制的雜訊，讓人無法回推出某一個人）。
🧠 記憶口訣漏、拆、問、騙 → 驗、密、噪
四風險：訓練數據洩漏（漏）、反向工程（拆）、提示詞攻擊（問）、對抗性攻擊（騙）；三防範：身份驗證與授權（驗）、加密（密）、差分隱私加雜訊（噪）。

📖 名詞小辭典

訓練數據洩漏Training Data Leakage
模型生成內容時無意間重複訓練資料中的片段或隱私資訊。例：模型吐出某人的電話與住址。
反向工程Reverse Engineering
透過分析模型行為，推斷模型參數或訓練資料。例：大量查詢 API，仿製出功能相近的模型。
提示詞攻擊Prompt Attack
透過精心設計或多次查詢的提示，試圖推斷、重建訓練資料中的敏感內容，或讓模型違反規則。例：反覆換句話問「你訓練資料裡某公司的內部文件寫了什麼」。
對抗性攻擊Adversarial Attack
精心設計的輸入（人眼幾乎看不出差異）操控模型輸出，甚至誘導洩密。例：在圖片加入微小雜訊，讓模型把停車標誌認成速限標誌。
身份驗證與授權Authentication & Authorization
確認使用者身分，並只給他該有的存取權限。例：只有人資部能查詢含薪資資料的 AI 助理。
差分隱私Differential Privacy
在資料或統計結果中加入經數學設計的雜訊，使任何單一個人的資料是否在其中都難以判斷，同時保留整體統計意義。例：公布各區平均收入時加入少量雜訊，無法回推某位居民的收入。
📌 考試重點四種常見風險：訓練數據洩漏、反向工程、提示詞攻擊、對抗性攻擊；三項防範：身份驗證與授權、加密技術（儲存與傳輸）、差分隱私等資料雜訊技術。
⚠️ 易混淆差分隱私是「加雜訊」；匿名化是「移除識別資訊」；加密是「沒金鑰看不懂」。另外常考：同態加密＝資料在加密狀態下仍可計算；聯邦學習＝原始資料不離開各端，只交換模型更新。
🚀 延伸與新進展考試範圍外
  • 訓練資料萃取攻擊（2021）：Carlini 等人在 2021 年的研究示範，可從大型語言模型中萃取出逐字的訓練資料（含個人資訊），是「訓練數據洩漏」的實證。
  • 間接提示注入（Indirect Prompt Injection）（2023）：Greshake 等人 2023 年的論文指出，攻擊者不必直接和模型對話，只要把惡意指令藏在模型會讀到的網頁、文件或 Email 中，就能操控整合了 LLM 的應用。RAG 與 AI Agent 普及後，這成為最主要的新型風險之一，對策包括把外部內容當「資料」不當「指令」、限制工具權限、敏感動作需人工確認。
  • 員工把機密貼進公開 AI 服務（2023 起）：資料外洩不一定來自駭客，常見的是員工為了方便，把原始碼、會議紀錄或客戶資料貼到外部聊天機器人。對策：企業版服務（約定不拿來訓練）、資料外洩防護（Data Loss Prevention, DLP）工具、明確的 AI 使用政策與教育訓練。

倫理與偏見 完整教材 ↗

💬 白話說模型是從歷史資料學的，歷史有偏見，模型就會照單全收、甚至放大：問「護理師」就畫女性、問「工程師」就畫男性。而且它像黑箱，說不清楚為什麼這樣判斷，出了事也不知道該怪誰。對策：資料要多元、用去偏見技術調整、持續監控輸出、推動可解釋 AI、引入第三方評估。
🧠 記憶口訣資料多元、決策透明、外部檢驗
三招對應指引：多樣化資料＋去偏見＋監控；透明決策流程＋XAI；第三方評估。

📖 名詞小辭典

偏見Bias
模型對特定性別、種族、文化等群體產生系統性的不公平傾向。例：圖像生成模型在膚色與性別分佈上不均衡。
黑箱Black Box
使用者無法理解 AI 的推理與決策過程，削弱可信度並使責任歸屬模糊。例：貸款被拒，但系統說不出原因。
去偏見技術Bias Mitigation Techniques
在資料、訓練或輸出階段降低偏見的方法，如重新加權、過濾規則、調整門檻。例：提高少數群體樣本權重後再訓練。
可解釋性 AIExplainable AI, XAI
讓人能理解 AI 為何做出某個決策的技術與研究。例：顯示「收入、負債比」是影響這次評分的前兩大因素。
第三方評估Third-party Audit / Assessment
由獨立外部單位客觀審視 AI 系統結果。例：委託外部機構檢測招募 AI 是否歧視。
責任歸屬Accountability
AI 出錯時由誰負責、如何追究與補救。例：明定 AI 產生的報價錯誤由哪個部門覆核負責。
📌 考試重點偏見來自歷史資料；黑箱削弱可信度並造成責任歸屬模糊。三項對策：確保訓練數據多樣性＋去偏見技術＋輸出監控、透明決策流程＋推進 XAI、引入第三方評估。
⚠️ 易混淆偏見檢測 vs 偏見緩解：「比較不同族群的預測分布或錯誤率」是檢測；「重新加權、過濾規則、調整門檻」是緩解。XAI 解決的是「看不懂」（透明），不是直接解決「不公平」。
🚀 延伸與新進展考試範圍外
  • 以原則對齊模型：Constitutional AI（2022）：Anthropic 提出讓模型依一組書面原則自我批評與修正、並用 AI 回饋取代部分人類標註，降低有害輸出。和 RLHF 的差別：價值判斷寫成可公開檢視的原則，較透明。
  • AI 評審本身也有偏見（2023）：用 LLM 評估 LLM 時，研究發現有位置、冗長、自我偏好等偏誤；因此公平性檢查不能完全交給 AI 評審，需搭配人工與第三方評估。
  • 台灣《人工智慧基本法》七大原則（2026）：包含「透明與可解釋」「公平與不歧視」「問責」等，與指引的黑箱、偏見、責任歸屬議題直接對應（詳見 6-4）。

生成式AI 與法規 完整教材 ↗

💬 白話說法規就是 AI 的交通規則：個資要匿名或假名化、使用前讓人知情同意（隱私）；訓練與生成不能侵犯別人的著作（資料來源合法）；醫療、自駕、公共政策這種「出事會出人命」的路段要特別嚴格審查（高風險限制）；出了事誰負責要先講好（責任分擔）；規則各地不同，所以要定期檢查、找法律專家一起訂內規（多層次對應）。
🧠 記憶口訣隱、源、高、責、多
資料隱私保護、資料來源合法性、高風險應用限制、責任分擔、多層次法規對應。代表法規：歐盟 GDPR、美國加州 CCPA。

📖 名詞小辭典

假名化Pseudonymization
以代號取代可直接識別的資訊，但保有對照表，必要時仍可還原；仍屬個資，需妥善保護。例：病歷中姓名改為「P0231」，對照表另外鎖在院內。
知情同意Informed Consent
讓當事人清楚了解資料用途後再同意使用。例：App 說明「對話紀錄將用於改善服務」並讓使用者勾選同意。
智慧財產權／著作權Intellectual Property, IP / Copyright
保護創作與發明的權利；生成圖像、文本、音樂時須避免侵犯第三方權利。例：生成與某知名角色幾乎相同的圖案用於商品可能侵權。
高風險應用High-risk Applications
錯誤可能造成重大傷害、須特別嚴格審查的應用，如重大醫療決策、自動駕駛、公共政策建議。例：AI 建議化療劑量必須經醫師與嚴格驗證。
合規性審查Compliance Review
檢查系統與流程是否符合法規與內部政策。例：上線前由法務確認個資處理符合規定。
內部使用政策Internal AI Use Policy
企業自訂的 AI 使用規範，與法律專家合作制定。例：規定哪些資料可輸入哪些 AI 工具。
📌 考試重點GDPR 與 CCPA 對資料匿名化處理、差分隱私技術應用提出要求；五項法規要點：資料隱私保護（匿名化或假名化、知情授權）、資料來源合法性（版權與 IP）、高風險應用限制（醫療、自駕、公共政策→技術標準與合規審查）、責任分擔、多層次法規對應（定期審查、與法律專家制定內部政策）。
⚠️ 易混淆匿名化 vs 假名化：匿名化後無法再識別個人；假名化可透過對照表還原，在 GDPR 下仍屬個人資料。GDPR 是歐盟、CCPA 是美國加州，別記反。

  • 亞洲其他 AI 立法（2025–2026）：日本《AI 推進法》2025 年 5 月通過、以促進為主、對民間不設罰則；韓國《AI 基本法》2026 年 1 月 22 日施行，含高影響 AI 與生成式 AI 標示等規定。

風險種類與管理策略 完整教材 ↗

💬 白話說先用風險矩陣把每個風險放進「發生機率 × 影響程度」的九宮格，紅區先處理。接著對每個風險選一種應對方式，就像面對「下雨」：
・迴避：今天不出門（暫緩高風險應用）；
・緩解：帶傘、穿雨鞋（從資料管理、內容審查著手降低機率或影響）；
・轉移：叫計程車、買保險（風險責任轉給第三方，但仍要監督）；
・接受：毛毛雨就算了，但準備備用衣服（影響有限時接受，並訂應急計畫）。
再加上兩個「基礎建設」：風險溯源（查清楚雨從哪來：資料來源與生成過程可追溯）與風險文化（全家都養成看天氣預報的習慣：培訓與通報獎勵）。
🧠 記憶口訣溯、文、接、緩、避、轉
A 風險溯源、B 風險文化、C 風險接受、D 風險緩解、E 風險迴避、F 風險轉移。四種經典應對可記「避、減、轉、受」。

📖 名詞小辭典

風險矩陣Risk Matrix
把風險的發生機率與影響程度交叉對比的定量／定性工具，用來排序優先處理順序。例：「客戶個資外洩」機率中、影響極高→列為紅色優先處理。
風險溯源Risk Traceability
審核資料來源的合法性與可靠性，並用可解釋性技術讓生成過程（輸入、處理邏輯、參數）可追溯。例：每份 AI 報告都記錄引用了哪些文件與模型版本。
風險文化Risk Culture
透過培訓、通報機制與獎勵，讓全員主動辨識與回報風險。例：員工回報 AI 錯誤回覆可獲得表揚。
風險接受Risk Acceptance
影響有限或無法完全避免時，評估容忍度後接受，並制定應急計畫。例：內部草稿工具偶爾錯字，接受並要求人工校對。
風險緩解Risk Mitigation
採取措施降低風險發生機率或影響：從資料管理開始、審查生成內容、定期更新控制策略。例：對外發布前加一道人工審稿。
風險迴避Risk Avoidance
技術不成熟或可能造成重大損害時，暫緩或不進行該應用，並設明確迴避標準。例：暫不讓 AI 直接給病患用藥建議。
風險轉移Risk Transfer
透過保險或合約，把部分或全部風險責任轉給第三方；仍須保留監控與審核權。例：購買資安保險、外包資安管理並簽訂責任條款。
風險容忍度Risk Tolerance / Appetite
組織願意承受的風險程度。例：行銷文案可容忍少量修改，財報數字零容忍。
應急計畫Contingency Plan
風險發生時的預先備案。例：AI 客服故障時自動轉接真人客服。
透明承諾Transparency Commitment
向外界公開風險管理做法，例如標示「此內容由 AI 生成」，以增加信任、減少誤解。例：網站文章底部註明「本文由 AI 協助撰寫並經編輯審閱」。
📌 考試重點風險評估核心＝依嚴重性與發生可能性排序（風險矩陣＝機率 × 影響）。情境判斷：暫緩不做→迴避；加審查、改善資料→緩解；買保險、外包簽約→轉移（仍需保留監控與審核權限）；影響有限、評估容忍度＋應急計畫→接受；審核資料來源、可追溯→溯源；培訓、通報獎勵→文化。透明承諾：標示「此內容由 AI 生成」。
⚠️ 易混淆轉移 ≠ 撒手不管：指引明寫即便轉移仍需保留監控與審核權限。接受 ≠ 忽略：要先評估容忍度並準備應急計畫。迴避 vs 緩解：迴避是「不做」，緩解是「做但降低風險」。
🚀 延伸與新進展考試範圍外
  • ISO/IEC 42001 AI 管理系統（2023）：2023 年 12 月發布的國際標準，要求組織建立 AI 政策、風險評估與處理、影響評估、持續改善等管理制度，並可接受第三方驗證。把指引的六種策略「制度化」，讓風險管理不是一次性的專案。
  • NIST AI RMF 與生成式 AI 剖繪（2023／2024）：以治理、對應、量測、管理四功能循環運作；生成式 AI 剖繪（AI 600-1，2024）列出生成式 AI 特有風險與建議行動，可直接拿來填風險矩陣的「風險清單」。
  • 來源標記落實「透明承諾」（2023 起）：除了文字標示「此內容由 AI 生成」，C2PA 來源憑證與 SynthID 等浮水印讓標示可被機器驗證；歐盟 AI Act 第 50 條也把標示 AI 生成內容列為法律義務（2026 年 8 月起適用）。
