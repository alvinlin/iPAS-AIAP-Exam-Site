一、基本概念與差異 完整教材 ↗白話版 ↗

範例 1

No Code vs Low Code：同一份報表，一個用設定檔「拖拉」出來，一個寫幾行程式客製

情境業務同事（市民開發者）想要一份「各地區月營收與年增率」報表。先用一個只吃 JSON 設定檔的小引擎做出來（No Code：不碰程式、但只能做引擎支援的事），再用幾行 pandas 加上引擎做不到的客製邏輯（Low Code）。

對應考點No Code：視覺化介面＋拖放，非技術者、快速原型Low Code：少量程式碼，複雜邏輯、企業級、客製彈性高市民開發者（Citizen Developer）NC/LC 的限制：只能做平台支援的事
Python
import json, numpy as np, pandas as pd
rng = np.random.default_rng(0)
sales = pd.DataFrame({"region": rng.choice(["北", "中", "南"], 240), "year": rng.choice([2025, 2026], 240),
                      "month": rng.integers(1, 13, 240), "revenue": rng.integers(50, 200, 240)})

# ── No Code：使用者只「設定」，不寫程式（真實平台用拖放介面產生這份設定）──
config = json.loads("""{
  "source": "sales", "group_by": ["region", "year"], "metric": {"column": "revenue", "agg": "sum"},
  "filter": {"column": "year", "op": ">=", "value": 2025}, "sort": "revenue desc", "top": 6 }""")

def nocode_engine(df, cfg):                                   # 引擎只支援有限的操作：這就是 No Code 的邊界
    ops = {">=": df[cfg["filter"]["column"]] >= cfg["filter"]["value"]}
    out = df[ops[cfg["filter"]["op"]]].groupby(cfg["group_by"])[cfg["metric"]["column"]].agg(cfg["metric"]["agg"]).reset_index()
    col, order = cfg["sort"].split(); out = out.sort_values(col, ascending=(order == "asc")).head(cfg["top"])
    return out
print("【No Code】設定檔產出：\n", nocode_engine(sales, config).to_string(index=False))
print("→ 想加『年增率』？引擎的設定裡沒有這個選項，No Code 做不到，要等平台支援或改用 Low Code")

# ── Low Code：在引擎產出上補幾行程式，做引擎沒有的邏輯 ──
base = nocode_engine(sales, config)
pivot = base.pivot(index="region", columns="year", values="revenue")
pivot["yoy_%"] = ((pivot[2026] / pivot[2025] - 1) * 100).round(1)                # 年增率：客製邏輯
pivot["flag"] = np.where(pivot["yoy_%"] < 0, "⚠ 衰退", "")                      # 商業規則
print("\n【Low Code】三行程式補上年增率與警示：\n", pivot.to_string())
print("\n適用對象：No Code → 非技術背景、快速原型、小型應用；Low Code → 具基本技術背景、複雜邏輯、要深度整合的企業應用")

🔍 結果解讀
  • No Code 的本質是「設定檔驅動」：使用者在介面上拖拉，平台把它變成類似 config 的描述再由引擎執行，所以完全不用寫程式，但也只能做引擎支援的操作。
  • 一旦需求超出平台（這裡的年增率），就要用 Low Code 寫少量程式補上客製邏輯，這就是指引說的「客製彈性較高、可深度整合」；代價是需要基本技術背景。
  • 業務同事能自己完成第一份報表，就是市民開發者的價值：把 IT 的排程從幾週縮到幾分鐘；但過度依賴也可能讓人不理解數字怎麼算出來的。
💡 延伸練習試著把 config 的 "agg" 改成 "mean"、"top" 改成 3，體會 No Code 的彈性；再想一個 Low Code 也做不到、必須寫完整程式的需求（例如串接外部 API 即時匯率）。

範例 2

生成式 AI 幫市民開發者：從自然語言「生成程式碼」、自動產出個人化行銷文案

情境模擬平台裡的 AI 助理：使用者打一句「計算 各地區 的 平均 營收」，助理產生對應的 pandas 程式並執行；再依顧客資料自動生成個人化文案。生成的部分用規則引擎代替 LLM，重點是看「生成 → 驗證 → 執行」的流程。

對應考點自動生成程式碼自動化行銷文案生成、個人化 App模板設計優化、數據分析與決策建議生成結果仍需驗證（多層次驗證＋人工審核）
Python
import re, numpy as np, pandas as pd
rng = np.random.default_rng(1)
df = pd.DataFrame({"地區": rng.choice(["北", "中", "南"], 90), "營收": rng.integers(50, 200, 90), "客數": rng.integers(10, 60, 90)})

# ── 1) 自然語言 → 程式碼（規則版的「text-to-code」；真實系統由 LLM 生成，流程相同）──
AGG = {"平均": "mean", "總和": "sum", "最大": "max", "筆數": "count"}
def text_to_code(q):
    m = re.match(r"計算 (\S+) 的 (\S+) (\S+)", q)
    if not m: return None
    by, agg, col = m.groups()
    return f'df.groupby("{by}")["{col}"].{AGG[agg]}().round(1)'
def validate(code, df):                                       # 多層次驗證：欄位存在？沒有危險操作？
    cols = re.findall(r'"([^"]+)"', code)
    if any(c not in df.columns for c in cols): return f"欄位不存在：{set(cols) - set(df.columns)}"
    if re.search(r"import|open\(|exec|eval|__", code): return "含危險操作，拒絕執行"
    return "OK"
for q in ["計算 地區 的 平均 營收", "計算 地區 的 總和 客數", "計算 門市 的 平均 營收"]:
    code = text_to_code(q); status = validate(code, df)
    print(f"「{q}」→ 生成：{code}\n   驗證：{status}")
    if status == "OK": print("   執行結果：", eval(code).to_dict())

# ── 2) 個人化行銷文案：模板 × 顧客資料 × 規則，再加人工審核關卡 ──
customers = pd.DataFrame({"name": ["小美", "阿明", "Jo"], "last_item": ["保濕精華", "藍牙耳機", "登山背包"],
                          "days_since": [12, 45, 90], "tier": ["gold", "silver", "gold"]})
def copywriter(c):
    hook = "老朋友回來看看！" if c.days_since > 60 else "新品到貨通知："
    perk = "VIP 專屬 85 折" if c.tier == "gold" else "滿額免運"
    return f"{c['name']}，{hook}您上次選購的「{c.last_item}」有新搭配款，{perk}，本週有效。"
customers["copy"] = customers.apply(copywriter, axis=1)
customers["needs_review"] = customers["copy"].str.contains("折|免費|保證")        # 含價格承諾的文案送人工審核
print("\n生成文案：")
for _, r in customers.iterrows(): print(f"  [{'待審核' if r.needs_review else '自動發送'}] {r['copy']}")

🔍 結果解讀
  • 「自然語言 → 程式碼 → 驗證 → 執行」是 AI 助理嵌入 NC/LC 平台的標準流程：生成的程式不能直接跑，要先檢查欄位是否存在、有沒有危險操作，這就是指引說的多層次驗證。
  • 第三句因為欄位不存在而被擋下：LLM 生成的程式常「看起來對」但引用不存在的欄位或函式，驗證層是必要的，不是可選的。
  • 文案生成用模板加顧客資料加規則就能做到個人化；含價格承諾的文案自動送人工審核，對應指引「人機協作機制」與「準確性：多層次驗證＋人工審核」。真實 LLM 的文案更自然，但審核關卡同樣不能省。
💡 延伸練習在 AGG 加入「中位數」，並多支援一種句型「找出 營收 最高 的 地區」；想想如果使用者打「刪除 所有 資料」，驗證層該怎麼擋。

範例 3

平台評選：六因素加權評分 + 三年總持有成本（TCO）與 ROI

情境三個候選 NC/LC 平台。先依指引的六個關鍵因素加權評分，再算三年 TCO（授權、建置、培訓、維護）與預估效益算 ROI，最後看兩種排名是否一致、該怎麼取捨。

對應考點目標用戶與技術需求、功能與擴展性、安全性與合規性成本與效益：TCO、ROI技術支援與社群資源、市場評價與成功案例加權評分法
Python
import pandas as pd
factors = ["目標用戶與技術需求", "功能與擴展性", "安全性與合規性", "成本效益", "技術支援與社群", "市場評價與案例"]
weights = [0.20, 0.20, 0.25, 0.15, 0.10, 0.10]                     # 金融業：安全合規權重最高
scores = pd.DataFrame({"平台 A（國際大廠）": [4, 5, 5, 2, 5, 5], "平台 B（本土新創）": [5, 3, 3, 5, 3, 2], "平台 C（開源自架）": [3, 4, 4, 4, 2, 3]}, index=factors)
weighted = (scores.T * weights).sum(axis=1).round(2)
print("六因素評分（1–5）：\n", scores.to_string())
print("\n加權總分：", weighted.sort_values(ascending=False).to_dict())

# 三年 TCO 與 ROI（萬元）
cost = pd.DataFrame({"授權/年": [120, 40, 0], "建置": [80, 30, 150], "培訓": [20, 10, 40], "維護/年": [10, 15, 60]},
                    index=scores.columns)
cost["3 年 TCO"] = cost["授權/年"] * 3 + cost["建置"] + cost["培訓"] + cost["維護/年"] * 3
benefit_per_year = pd.Series([150, 110, 130], index=scores.columns)    # 預估年效益（省下的人力＋新增營收）
cost["3 年效益"] = benefit_per_year * 3
cost["ROI"] = ((cost["3 年效益"] - cost["3 年 TCO"]) / cost["3 年 TCO"]).round(2)
print("\n", cost.to_string())
print("\n→ 加權評分第一的平台 A 其 ROI 最低；ROI 最高的平台 B 安全合規只有 3 分。")
print("  決策不是取最高分，而是先設『門檻』（例如安全合規 ≥ 4）再比 ROI：", [p for p in scores.columns if scores.loc["安全性與合規性", p] >= 4])

🔍 結果解讀
  • 六個關鍵因素的權重要依產業調整：金融、醫療把安全合規放最重，新創可能把成本效益放最重；同一份評分換一組權重，排名就可能翻轉。

  • 加權分第一與 ROI 第一不是同一個平台，是常見情況；指引列的六因素裡有些是「門檻型」（合規不過就不能用）、有些是「越高越好型」，先過門檻再比 ROI 才是合理的決策流程。

範例 4

標記化與向量化：同一句話切成幾個 token？中英文差多少？token 數怎麼變成 API 成本？

情境用三種切法（字元、詞、簡化的子詞）把中英文句子標記化，看 token 數差多少；把 token 向量化後算相似度；最後估算一個客服機器人每月的 token 用量與成本（單價為假設值）。

對應考點標記化（Tokenization）向量化表示（Vectorization）上下文長度與 token 計價數據清洗：去雜訊
Python
import re, numpy as np
zh = "我想查詢上個月的帳單明細並更改付款方式"
en = "I want to check last month's bill and change my payment method"
char_tok = lambda s: list(s.replace(" ", ""))
word_tok = lambda s: re.findall(r"[A-Za-z']+|[一-鿿]+", s)
def subword_tok(s, maxlen=2):                                # 簡化子詞：中文每 2 字一個、英文依常見字首字尾切
    out = []

        else: out += [p for p in re.split(r"(ing|ment|'s|ed)$", w) if p]
    return out

範例 5

推理機制三參數：溫度、Top-k、核採樣（Top-p）怎麼改變「下一個字」的機率分佈

情境模型對下一個字給出 10 個候選的原始分數（logits）。分別套用低溫／高溫、Top-k=3、Top-p=0.9，印出每種設定下的機率分佈，再各抽樣 20 次看輸出有多「保守」或「發散」。

對應考點溫度參數：控制隨機性，低溫保守、高溫創意Top-k：只保留前 k 個候選核採樣 Top-p：累積機率達閾值（如 0.9）為止AI 幻覺與輸出變異
Python
import numpy as np
rng = np.random.default_rng(0)
tokens = ["的", "很", "是", "了", "在", "好", "有", "也", "不", "就"]
logits = np.array([3.0, 2.6, 2.2, 1.5, 1.0, 0.5, 0.2, -0.3, -0.8, -1.5])      # 模型對下一個字的原始分數

def softmax(z): e = np.exp(z - z.max()); return e / e.sum()
def with_temperature(z, T): return softmax(z / T)
def top_k(p, k):
    keep = np.argsort(p)[::-1][:k]; q = np.zeros_like(p); q[keep] = p[keep]; return q / q.sum()
def top_p(p, thr):
    order = np.argsort(p)[::-1]; cum = np.cumsum(p[order])
    keep = order[:int(np.searchsorted(cum, thr)) + 1]                           # 累積機率剛好達到閾值為止
    q = np.zeros_like(p); q[keep] = p[keep]; return q / q.sum()

settings = {"原始 (T=1)": softmax(logits), "低溫 T=0.3": with_temperature(logits, 0.3), "高溫 T=2.0": with_temperature(logits, 2.0),
            "Top-k=3": top_k(softmax(logits), 3), "Top-p=0.9": top_p(softmax(logits), 0.9)}
print(f"{'設定':12s}" + "".join(f"{t:>6s}" for t in tokens) + "   候選數  抽 20 次的結果")
for name, p in settings.items():
    draws = "".join(rng.choice(tokens, p=p) for _ in range(20))
    print(f"{name:12s}" + "".join(f"{v:6.2f}" for v in p) + f"{int((p > 0).sum()):7d}   {draws}")
print("\n熵（不確定性，越大越隨機）：", {k: round(float(-(p[p > 0] * np.log(p[p > 0])).sum()), 2) for k, p in settings.items()})
print("Top-p 保留的候選數會隨分佈自動調整：分佈尖時少、分佈平時多；Top-k 永遠固定 k 個")

範例 6

RLHF 的核心想法：用人類「A 比 B 好」的比較訓練獎勵模型，再用它挑出最貼近使用者的回答

情境對同一個問題收集多組「兩個回答哪個比較好」的人類判斷，用邏輯迴歸訓練一個獎勵模型（輸入是回答的特徵：長度、禮貌、是否切題、是否有具體步驟），然後對新的候選回答打分、挑最好的（best-of-n），看它的偏好是否學得像人。

對應考點RLHF 貼近用戶需求獎勵模型（Reward Model）由人類偏好訓練Transformer／GPT 預訓練 → 微調 → 對齊Best-of-n 重排序
Python
import numpy as np
from sklearn.linear_model import LogisticRegression
rng = np.random.default_rng(0)
FEATS = ["長度(百字)", "禮貌用語", "切題程度", "具體步驟", "過度推銷"]
def human_pref(f):                                            # 模擬人類的真實偏好（獎勵模型要學的對象，實務上不可知）
    return 0.2*f[0] + 0.8*f[1] + 1.5*f[2] + 1.0*f[3] - 1.2*f[4] - 0.3*max(0, f[0] - 3)**2   # 太長會被扣分
def random_answer(): return np.array([rng.uniform(0.3, 6), rng.integers(0, 2), rng.uniform(0, 1), rng.integers(0, 2), rng.integers(0, 2)], float)

# 1) 收集成對比較：標註者看 A、B 兩個回答，選比較好的那個（允許 10% 的標註雜訊）
pairs, labels = [], []
for _ in range(600):
    a, b = random_answer(), random_answer()
    better_a = human_pref(a) > human_pref(b)
    if rng.random() < 0.1: better_a = not better_a
    pairs.append(a - b); labels.append(int(better_a))                              # 以特徵差當輸入：P(A 勝) = σ(w·(A−B))
reward = LogisticRegression(fit_intercept=False).fit(np.array(pairs), labels)      # 這就是 Bradley-Terry 式的獎勵模型
print("獎勵模型學到的權重：", dict(zip(FEATS, reward.coef_[0].round(2).tolist())))
print("→ 切題、具體步驟、禮貌為正；過度推銷為負：和人類偏好方向一致，雖然人類從沒給過『分數』，只給過『比較』\n")

# 2) Best-of-n：模型產生 6 個候選回答，用獎勵模型挑最好的
cands = {"A 短而冷淡": [0.5, 0, 0.6, 0, 0], "B 禮貌但離題": [2, 1, 0.2, 0, 0], "C 切題有步驟": [2.5, 1, 0.9, 1, 0],
         "D 切題但狂推銷": [2.5, 1, 0.9, 1, 1], "E 超長完整": [7, 1, 0.9, 1, 0], "F 中等無步驟": [2, 1, 0.7, 0, 0]}
score = lambda f: float(reward.coef_[0] @ np.array(f))
ranked = sorted(cands, key=lambda k: -score(cands[k]))
for k in ranked: print(f"  獎勵分 {score(cands[k]):6.2f}  {k}")
print(f"\nBest-of-6 選出：{ranked[0]}；人類真實偏好最高的是：{max(cands, key=lambda k: human_pref(np.array(cands[k], float)))}")
print("實際 RLHF 下一步是用這個獎勵當強化學習的回饋去更新語言模型本身（PPO），讓它直接生成高分回答，而不只是事後挑選")

範例 7

輕量化與效能優化：把模型權重從 FP32 量化到 INT8，體積縮四倍、輸出差多少？

情境用一個小型嵌入矩陣與一層線性變換模擬模型權重。做 INT8 量化（每列一個縮放因子），比較體積、權重誤差與輸出餘弦相似度；再比較「一次一筆」與「批次」推論的時間差，理解效能優化的兩個常見手段。

對應考點輕量化與個人化：模型壓縮、量化效能優化：推理加速、批次推論安全性：本地部署、資料加密的前提是模型要跑得動邊緣運算 vLLM 概念
Python
import numpy as np, time
rng = np.random.default_rng(0)
vocab, dim, hidden = 2000, 64, 512
E = rng.normal(0, 0.5, (vocab, dim)).astype(np.float32)        # 嵌入矩陣（模型權重的一部分）
W = rng.normal(0, 0.1, (dim, hidden)).astype(np.float32)       # 一層線性變換
params = E.size + W.size

def quantize_rows(M):                                           # 每列一個縮放因子，映到 -127..127 的整數
    s = np.abs(M).max(axis=1, keepdims=True) / 127
    q = np.clip(np.round(M / s), -127, 127).astype(np.int8)
    return q, s.astype(np.float32)
Eq, Es = quantize_rows(E); Wq, Ws = quantize_rows(W)
E_deq, W_deq = Eq * Es, Wq * Ws                                   # 推論時反量化（或直接用整數運算）
size_fp32 = params * 4 / 1024; size_int8 = (params * 1 + (vocab + dim) * 4) / 1024
print(f"參數量 {params:,}：FP32 {size_fp32:.0f} KB → INT8 {size_int8:.0f} KB（{size_fp32 / size_int8:.1f} 倍）")
print(f"權重平均絕對誤差：嵌入 {np.abs(E - E_deq).mean():.5f}（權重尺度 {np.abs(E).mean():.3f}），線性層 {np.abs(W - W_deq).mean():.5f}")

ids = rng.integers(0, vocab, 32)
out32 = np.tanh(E[ids] @ W); out8 = np.tanh(E_deq[ids] @ W_deq)
cos = (out32 * out8).sum(1) / (np.linalg.norm(out32, axis=1) * np.linalg.norm(out8, axis=1))
print(f"32 個輸入的輸出向量餘弦相似度：平均 {cos.mean():.4f}，最低 {cos.min():.4f} → 幾乎沒差")

# 推理加速：逐筆 vs 批次
X = E[rng.integers(0, vocab, 4096)]
t = time.perf_counter(); _ = [np.tanh(x @ W) for x in X]; t_one = time.perf_counter() - t
t = time.perf_counter(); _ = np.tanh(X @ W); t_batch = time.perf_counter() - t
print(f"\n4096 筆推論：逐筆 {t_one*1000:.1f} ms，批次 {t_batch*1000:.2f} ms → 快 {t_one / t_batch:.1f} 倍（矩陣越大差距越大；vLLM 等推理引擎的核心就是把請求湊成批次）")
print("4-bit 量化再省一半，但誤差放大；手機、邊緣裝置與本地部署都靠這些技術才跑得動")

  • INT8 量化把每個權重從 4 bytes 變 1 byte，模型體積縮到四分之一，而輸出向量的餘弦相似度仍接近 1：訓練好的模型對權重的小誤差很不敏感，這就是輕量化可行的原因。
  • 每列一個縮放因子（而不是整個矩陣一個）能讓誤差更小，是常見的量化技巧；4-bit 再省一半但誤差明顯放大，通常搭配量化感知訓練。
  • 批次推論比逐筆快好幾倍，因為矩陣乘法一次算完、硬體利用率高；這裡的矩陣很小所以差距有限，真實模型在 GPU 上差距可達數十倍。vLLM 這類推理引擎的核心就是把同時到達的請求湊成批次並管理記憶體，這是「效能優化」趨勢的具體內容。

def smart_check(k):
    has_num = bool(re.search(r"\d", k)); has_time = bool(re.search(r"個月|週|天|年|季", k))
    has_base = bool(re.search(r"從|目前|基準", k)); has_measure = bool(re.search(r"衡量|檢核|抽檢|%|分鐘|小時", k))
    score = sum([has_num, has_time, has_base, has_measure])
    return score, "".join("✔" if b else "✘" for b in [has_num, has_time, has_base, has_measure])
print(f"{'KPI':52s} 數字/期限/基準/量法  評分")

import numpy as np
from scipy import stats
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, recall_score
rng = np.random.default_rng(0)
def week_data(w, n=500):
    shift = 2.0 if w >= 6 else 0.0                                   # 第 6 週起客訴內容特徵的分佈改變
    X = rng.normal([0, 0], 1, (n, 2)) + [shift, 0]
    y = ((X[:, 0] - shift) * 1.0 + X[:, 1] * 0.5 + rng.normal(0, 0.6, n) > 0).astype(int)   # 真實規則也隨之移動
    return X, y
X0, y0 = week_data(0, 2000)
model = LogisticRegression().fit(X0, y0); ref = X0[:, 0]
print(f"{'週':>3s}{'Accuracy':>9s}{'Recall':>8s}{'ErrorRate':>10s}{'KS p值':>9s}  動作")
for w in range(1, 11):
    X, y = week_data(w)
    pred = model.predict(X)
    acc, rec = accuracy_score(y, pred), recall_score(y, pred)
    ks_p = stats.ks_2samp(ref, X[:, 0]).pvalue                         # 輸入分佈 vs 訓練時的分佈
    action = ""
    if ks_p < 0.01: action = "⚠ 數據漂移"
    if acc < 0.80:                                                     # 跌破門檻 → 自動重訓（用最近資料）
        model = LogisticRegression().fit(X, y); ref = X[:, 0]
        action += "  → 觸發重新訓練（用本週標註資料）"
    print(f"{w:3d}{acc:9.3f}{rec:8.3f}{1 - acc:10.3f}{ks_p:9.4f}  {action}")
print("\n回饋機制：每週把人工修正過的分派結果當新標籤回流 → 算指標 → 漂移或指標跌破門檻就重訓 → 新模型先小流量驗證再全量")

import numpy as np
def evaluate(capex=400, opex=120, direct=300, indirect=80, years=4, rate=0.08, adoption=1.0, verbose=False):
    cash = [-capex] + [(direct + indirect) * adoption - opex] * years
    npv = sum(c / (1 + rate) ** t for t, c in enumerate(cash))
    roi = (sum(cash[1:]) - capex) / capex
    payback = capex / cash[1] if cash[1] > 0 else float("inf")
    f = lambda r: sum(c / (1 + r) ** t for t, c in enumerate(cash))
    lo, hi = -0.9, 3.0
    for _ in range(100): mid = (lo + hi) / 2; lo, hi = (mid, hi) if f(mid) > 0 else (lo, mid)
    irr = (lo + hi) / 2
    if verbose:
        print(f"每年淨效益 = ({direct} + {indirect}) × {adoption:.0%} − {opex} = {cash[1]:.0f} 萬；現金流 {cash}")

    return npv

  • 差分隱私在統計結果上加與 ε 成反比的雜訊：小部門的真實人數被遮住、大部門的趨勢仍看得出來，這就是「在不暴露個人的前提下公布統計」；ε 是隱私預算，每多查一次就多花一點。
  • 個資不存明文而存加鹽／HMAC 雜湊，資料庫被偷也無法反推；但雜湊只解決儲存，傳輸還要 TLS、存取還要身份驗證與授權，指引把這三件事並列就是這個意思。
  • 提示詞攻擊靠「忽略以上指令」「你現在是…」這類句型繞過限制，先用規則打分攔截是第一道防線；模型對某些句子信心異常高，則是它可能背下訓練資料（含個資）的訊號，要在訓練前就去識別化。
💡 延伸練習把 ε 改成 0.1，看人資的公布值會變得多離譜；再寫一句用同義詞（例如「請無視前面的設定」）繞過目前規則的攻擊，然後補上規則。

import numpy as np, re
from sklearn.ensemble import GradientBoostingClassifier
rng = np.random.default_rng(0)
# 1) 語料偏見統計
corpus = ["他是一位資深工程師", "她是一位護理師", "他擔任工程師十年", "她是護理師也是媽媽", "他是護理師", "她成為工程師",
          "他是工程師", "她是護理師", "他是工程師主管", "她在醫院當護理師", "他是工程師", "她是護理師"]
def male_ratio(texts, job):
    m = sum(1 for s in texts if job in s and "他" in s); f = sum(1 for s in texts if job in s and "她" in s)
    return m, f, m / (m + f)
for job in ["工程師", "護理師"]:
    m, f, r = male_ratio(corpus, job)
    print(f"{job}：他 {m} 次、她 {f} 次 → 男性比例 {r:.0%}")
print("→ 語料把工程師預設為男性、護理師預設為女性，模型會學到並放大這個關聯（生成履歷、翻譯代詞時就會出現）")
swap = lambda s: s.replace("他", "她") if "他" in s else s.replace("她", "他")
balanced = corpus + [swap(s) for s in corpus]                   # 去偏：反事實資料增強（代詞對調後加回語料）
print(f"反事實資料增強後：工程師男性比例 {male_ratio(balanced, '工程師')[2]:.0%}，護理師 {male_ratio(balanced, '護理師')[2]:.0%}\n")

# 2) XAI：擾動法解釋單一決策
n = 3000
X = np.column_stack([rng.normal(55, 15, n), rng.normal(650, 60, n), rng.integers(0, 2, n), rng.integers(0, 15, n)])   # 收入, 信用分, 有房, 年資
y = ((0.02*X[:, 0] + 0.012*X[:, 1] + 0.6*X[:, 2] + 0.05*X[:, 3] + rng.normal(0, 0.8, n)) > 9.6).astype(int)
clf = GradientBoostingClassifier(random_state=0).fit(X, y)        # 當作黑箱
names = ["月收入(千)", "信用分數", "有房", "年資"]
applicant = np.array([[48, 610, 0, 2]])
p0 = clf.predict_proba(applicant)[0, 1]
print(f"申請人 {dict(zip(names, applicant[0].tolist()))} → 核准機率 {p0:.2f} → {'核准' if p0 >= .5 else '拒絕'}")
print("擾動法解釋：每次只改一個特徵，看核准機率變多少")
effects = {}
for j, delta, label in [(0, 15, "+15 千"), (1, 60, "+60 分"), (2, 1, "改為有房"), (3, 8, "+8 年")]:
    x2 = applicant.copy(); x2[0, j] += delta
    effects[names[j]] = clf.predict_proba(x2)[0, 1] - p0
    print(f"  {names[j]:8s} {label:8s} → {p0 + effects[names[j]]:.2f}（{effects[names[j]]:+.2f}）")
top = max(effects, key=effects.get)
print(f"人看得懂的解釋：『主要因為{top}偏低（{int(applicant[0, names.index(top)])}）；單獨提高它，核准機率從 {p0:.2f} 升到 {p0 + effects[top]:.2f}，是四個因素中影響最大的；其次是{sorted(effects, key=effects.get)[-2]}。』")
print("→ LIME 把這種擾動做得更系統（在附近抽很多點、擬合一個線性模型），SHAP 則用博弈論分配每個特徵的貢獻")
